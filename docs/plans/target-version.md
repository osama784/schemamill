# Target version — plan rendering honors a declared PostgreSQL major

**Status:** built · **Last updated:** 2026-11-06

Version handling is one of the [core domain's hard problems](../domain/core-domain.md): catalog shape, DDL support, and lock behavior differ across PostgreSQL majors, and offline work has to state the version it generates for. This slice ships the offline half of that statement: `renderSql` accepts a declared PostgreSQL major, `plan` exposes it as `--target-version`, and the two statements the renderer synthesizes above the documented floor refuse by name instead of emitting SQL the declared server rejects. Live detection, credentials, and transport stay with [#57](https://github.com/osama784/schemamill/issues/57). The durable decisions are recorded in [ADR 0024](../adr/0024-synthesized-forms-consult-the-target-version.md); the slice shipped in [#141](https://github.com/osama784/schemamill/issues/141).

## Goal

The offline half of [core-domain hard problem #5](../domain/core-domain.md): a declared PostgreSQL major that plan rendering honors — the renderer synthesizes nothing above the declared target, states the model's declarations as declared, and refuses by name when a synthesized form postdates the target — while live server detection stays with [#57](https://github.com/osama784/schemamill/issues/57).

## Scope

**In:** the `RenderOptions.targetVersion` render option, defaulting to `MIN_TARGET_VERSION` (13) and accepting any integer at or above it; the `plan --target-version <major>` flag, restricted to the declared 13–18 span and validated before any filesystem access as a usage error; the two synthesized consumers — `SET STORAGE DEFAULT` at PostgreSQL 16 and newer, `SET COMPRESSION default` at PostgreSQL 14 and newer — refused at the emitter with exact messages; the live harness rendering every scene for the server under test; and [ADR 0024](../adr/0024-synthesized-forms-consult-the-target-version.md), this plan, the `CONTEXT.md` term, the changelog, and the mutable-docs sweep.

**Out, named — never silent:** live server detection, credentials, and transport ([#57](https://github.com/osama784/schemamill/issues/57)); declaration validation against the target (the per-form residual in D5); an `export --target-version` or `compare --target-version` flag (export renders creates only, compare renders nothing); multi-engine dialect selection; and the render-refusal guard's conventional-name arithmetic, which has no version branch and is not a form gate.

## Decisions

- **D1 — Placement: a render option (issue Q1).** `renderSql(plan, options?: RenderOptions)` with `RenderOptions = { readonly targetVersion?: number }`, exported from `render.ts` and the package barrel beside `MIN_TARGET_VERSION` (13) and `MAX_TARGET_VERSION` (18). The version decides SQL text, and the text is born in `renderSql`. No `Model`, workspace, or `Plan` field: the model stays engine-general ([ADR 0004](../adr/0004-postgresql-only-dialect-seam.md)), the workspace stays bare ([ADR 0010](../adr/0010-workspace-container.md)), and a `Plan` field would drag the target into snapshot comparison and every plan literal. A bound renderer factory was rejected for having no consumer.
- **D2 — The default is 13 (issue Q2).** Unset means "generate for the oldest supported major", so the documented floor becomes true: any synthesized form above it refuses instead of being emitted. This is a behavior change for a plan that resets storage or compression — it rendered before and now refuses until the target says 16 or 14. A default of 16 or 18 would be behavior-preserving but would document an assumption the offline tool cannot verify and keep silently emitting SQL a 13 server rejects, which is the bug this slice fixes. A "no default, always refuse when a version decision is needed" was rejected as breaking every reset plan and golden for no extra safety, since 13 is the declared floor and every other emitted form is 13-safe.
- **D3 — A closed consumer list (issue Q3).** The list began with exactly two synthesized forms that refuse: `SET STORAGE DEFAULT` requires 16; `SET COMPRESSION default` requires 14. The list is complete because we enumerated the whole emitted grammar — `renderStep`'s exhaustive switch plus its helpers — as forty statement/clause forms: the transaction wrappers; schema, table, column, constraint, index, sequence, extension, view, and comment statements; identity and persistence changes; `SET STORAGE`; and `SET COMPRESSION`. Each form was checked against primary sources: every form other than these two resets is either available at 13 or a declaration the model carries (D5). `SET STORAGE DEFAULT` entered the grammar in PostgreSQL 16 (commit `b9424d014e1`; `DEFAULT` is reserved in 15 and earlier), and `SET COMPRESSION`, `default` included, in 14. Nothing here adapts its emission: resetting storage or compression offline cannot be expressed on an older server because the type's default storage is not modeled and there is no alternate statement, so refusal is the only sound option. [ADR 0025](../adr/0025-in-place-foreign-key-enforcement-flips.md) adds a third consumer of a different class: the in-place foreign-key enforcement form PostgreSQL 18 accepts ([#133](https://github.com/osama784/schemamill/issues/133)) is a choice between that form and the equivalent drop/add pair, so below 18 the renderer selects the fallback rather than refusing. The closed list is therefore two refusing synthesized forms plus this one fallback-carrying form choice.
- **D4 — Refusal, not a warning (issue Q4).** The gate sits in the emitter — the place that decides the value — so the refusal cannot drift from the emission logic and naturally yields the first offending statement in plan order. A pre-pass re-deriving the carrier/standalone decision was rejected as duplicate logic; post-render string scanning was rejected as fragile. Both gates throw `RenderRefusalError` with one pinned shape, one line each, where `<table>` is the schema-qualified minimally quoted table and `<column>` the quoted column:
  - `refusing to render for PostgreSQL <target>: SET STORAGE DEFAULT on <table> column <column> needs PostgreSQL 16 or newer`
  - `refusing to render for PostgreSQL <target>: SET COMPRESSION default on <table> column <column> needs PostgreSQL 14 or newer`

  The message stays library-level and never names the CLI flag, because the package is a seam for a future studio. The CLI prints one `schemamill: <message>` stderr line after the plan display and exits 1, the existing #48 contract. A warning would leave unsatisfiable SQL on stdout; a plan either renders for its declared target or is refused.
- **D5 — Declarations render as declared.** An explicit storage letter or compression method, a named not-null fact, and `NOT ENFORCED` are declarations the model carries; the renderer states them at every target, exactly as before. A test renders one declaration-carrying plan at 13, 14, 16, and 18 and asserts byte-identical output. The residual — a declared target below a declaration's own floor is not validated — is named per form, and the silent row is the one genuinely dangerous case:

  | Declaration | On a target below its floor | Loudness |
  |---|---|---|
  | PostgreSQL 18 named `NOT NULL` (inline or `ADD CONSTRAINT … NOT NULL`) | 13–17 accept the inline form and discard the name — no `pg_constraint` row, so a later `COMMENT ON CONSTRAINT` fails | **silent** |
  | `NOT ENFORCED` on a check or foreign key | 13–17 reject the statement | loud syntax error at apply |
  | explicit `COMPRESSION` method | 13 rejects the statement | loud syntax error at apply |
  | explicit `STORAGE` letter | valid on all of 13–18 | harmless |

  Validating declarations would re-litigate [ADR 0012](../adr/0012-constraint-attributes-travel-the-model.md); it needs its own slice and ADR, and the table is that slice's body.
- **D6 — `plan()` stays version-free.** It gains no parameter: the two reset consumers are emission-time, and a parameter without a consumer is dead surface. Keeping `Plan` version-free means one plan renders for several targets, which is why the live harness and the multi-target tests are cheap. [#133](https://github.com/osama784/schemamill/issues/133) was predicted to add a plan-time parameter when a plan-time decision exists; it did not. Its in-place enforcement choice is a render-time pairing of the plan's existing drop and add ([ADR 0025](../adr/0025-in-place-foreign-key-enforcement-flips.md)), so `plan()` still takes no target and one plan renders the drop/add pair below 18 and the ALTER at 18 and above.
- **D7 — Guard order and the seam are unchanged.** `renderSql` still runs `assertGroupsTileSteps` → `assertIndexNamesUnique` → emissions, so a malformed plan or duplicate index name refuses first, preserving #48's pinned precedence. `SqlRenderer`'s `render(plan)` seam is untouched: `renderSql(plan, options?)` satisfies it and `sqlRenderer` keeps the default 13; extending the seam is deferred until a studio consumer exists.
- **D8 — The live harness renders for the server under test.** Every `renderSql` call in `live-pg.test.ts` passes `{ targetVersion: serverMajor }`, and `ScenePlanCheck.failure` gained an optional third `serverMajor` argument passed through by `assertPlanChecks`, so a plan-check probe renders for the same server that applies it. The drive-by floor correction is named: `introspection-flags` declared no floor but its target carries an explicit `SET COMPRESSION pglz`, which PostgreSQL 13 rejects, so it now declares `minServerMajor: 14`; `column-attributes` already declared 16 and is the only scene with a storage reset.

## Consequences

- **Reset plans need a declared target.** A plan that resets column storage refuses below a target of 16, and one that resets compression below 14 — until the target is declared. The change is loud and named three ways: the pinned refusal line, `plan --help`, and the changelog's `### Changed` bullet.
- **The documented PostgreSQL 13 floor is now true.** Before this slice, a 13-floor plan could render `SET STORAGE DEFAULT` and `SET COMPRESSION default`; now the default target refuses them, so the floor claim in [ADR 0015](../adr/0015-column-attributes-travel-the-model.md) and the [introspection attributes plan](./introspection-attributes.md) is enforced rather than aspirational.
- **A target above 18 is accepted and trivially satisfied.** The renderer only knows forms through 18, so a newer target behaves like 18 and every synthesized form is available; the CLI still restricts user input to the declared 13–18 span.
- **The PostgreSQL 13 live leg now runs in CI.** [#166](https://github.com/osama784/schemamill/issues/166) added a `verify-postgres` matrix that runs against PostgreSQL 13 and 18 services with matching client tools. `constraint-create` and `introspection-constraints` pin PostgreSQL 14+ `EXTRACT` deparse (`(0)::numeric`; 13 returns `double precision` and deparses as `date_part('epoch'::text, …)`), so they are floored at 14 and a 13 server skips them by name. The historical host/CI limits stay the reason the leg was deferred: this host had only PostgreSQL 16.15 and CI had only 18, no 13/14/15 package existed in the configured sources, and there was no Docker or podman, so a PG13 CI job was a workflow and service change outside the slice and proposed at bookkeeping ([#57](https://github.com/osama784/schemamill/issues/57) remains the live-detection owner).
- **The declaration gap stays open by design.** A declared target below a declaration's floor still renders as declared; the named-`NOT NULL` row above is silent on 13–17 until the declaration-validation follow-up lands.

## Acceptance

- **Unit tests, per consumer and both directions.** The default (13) refuses a storage and a compression reset with the exact messages; targets 14 and 15 render the compression reset and refuse the storage reset; target 16 renders both; target 13 refuses both; the first offender in plan order names itself; odd identifiers quote exactly as the SQL does; the merged-`TYPE` carrier branch emits no reset and never refuses at 13; a reset-free plan and a declaration-carrying plan render byte-identically at 13, 14, 16, and 18; `renderSql(plan, {})` behaves as the default; and a target of 12 or 13.5 throws the pinned plain `Error`.
- **The CLI refusal and both usage errors.** `plan --target-version 13` prints the version-free display on stdout, one exact refusal line on stderr, and exits 1; target 14 refuses the storage reset while admitting compression; `12`, `19`, `13.4`, and `abc` are the exact usage error `error: --target-version must be a PostgreSQL major from 13 to 18` with empty stdout and exit 1, proven with nonexistent paths so validation precedes any filesystem access; a missing flag value is Commander's argument-missing error; an explicit target leaves a reset-free plan byte-identical; and `compare --target-version` is Commander's unknown-option error, pinning the deliberate omission.
- **Golden bytes are unchanged.** `column-attributes` is the only golden carrying these forms: its postgres golden renders with `{ targetVersion: 16 }`, its CLI plan scene passes `--target-version 16`, and every golden file stays byte-identical. Every golden that takes no explicit options is also rendered at `{ targetVersion: 13 }` by the helper — the 13-floor sweep across the 14 non-reset goldens — proving the swept plans need no target above 13; a golden declaring its own target, like `column-attributes` and the later target-18-only `foreign-key-enforcement`, stays out of that sweep.
- **Live evidence.** On PostgreSQL 16.15 the live suite is 483 tests, 469 pass, 4 skipped — the four PostgreSQL 18 scenes (`constraint-attributes`, `not-null-constraint-names`, `enforcement-in-place`, and `introspection-flags-constraints-18`) skip by name — and `column-attributes` applies both reset forms. Dropping the target from the migration render fails that scene with the pinned storage refusal, so the harness wiring is load-bearing. The CI matrix adds a PostgreSQL 13 leg: the scenes floored above 13 skip there by name, and the PostgreSQL 18 leg runs the full corpus.
- **Gates and counts.** `pnpm build`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm format:check` are green, and `pnpm docs:counts --check` reports zero stale.
- **The record.** ADR 0024 is accepted, `CONTEXT.md` defines **Target version**, and `plan --help` documents `--target-version <major>  PostgreSQL major (13-18) (default: "13")`.

## Done means

The flag is documented in `plan --help`, the plan doc and [ADR 0024](../adr/0024-synthesized-forms-consult-the-target-version.md) are merged, the live harness renders for the server under test, a `[Unreleased]` changelog entry records the flag and the behavior change, every mutable doc states the new split, and the five gates plus `docs:counts --check` are green on the final tree.

## Deferred

Every item names its owner; nothing is silently dropped.

- **A `Model` or workspace target field** (the issue's leaning) — rejected for v1; a `factory:proposed` follow-up at bookkeeping, to be decided with a workspace-format change.
- **`export --target-version`** — gains the flag with its first version-sensitive form; owner: the declaration-validation follow-up.
- **`compare --target-version`** — compare renders nothing; owner: [#133](https://github.com/osama784/schemamill/issues/133) or the hazard version-awareness slice.
- **Declaration validation against the target** (named `NOT NULL`, `NOT ENFORCED`, explicit compression below 14) — re-litigates ADR 0012; a `factory:proposed` follow-up at bookkeeping with its own ADR, and D5's table is its body.
- **Live server detection, credentials, and transport** — [#57](https://github.com/osama784/schemamill/issues/57).
- **#133's in-place `ALTER CONSTRAINT … ENFORCED`** — shipped at target 18 as a render-time form choice with an equivalent drop/add fallback ([ADR 0025](../adr/0025-in-place-foreign-key-enforcement-flips.md)); `plan()` stayed version-free, so the predicted plan-time target parameter did not materialize ([#133](https://github.com/osama784/schemamill/issues/133)).
- **Hazard version-awareness** — [hazards.md](./hazards.md) stays true because analysis reads two models and a plan; its own `factory:proposed` follow-up.
- **Render-refusal guard "floors"** — the guard is conventional-name arithmetic, not a form gate; [render-refusal.md](./render-refusal.md)'s slice B owns occupancy and baseline.
- **Extending the `SqlRenderer` seam with options** — when a studio consumer exists; `factory:proposed` follow-up.
- **Multi-target batch rendering** (one plan rendered for several targets in one command) — `factory:proposed` follow-up.
- **Pre-existing declaration floors in the live corpus** — the `introspection-flags` floor is corrected here (D8); any other scene carrying a declaration above the base floor is D5's class, covered by the declaration-validation follow-up.
