# Import long tail — extensions, grants, and exotic objects

**Status:** planned · **Last updated:** 2026-11-20

Real dumps carry far more than the imported subset: extensions, privileges, comments, triggers, partitioning, and whole object families the canonical model does not yet name. Views and materialized views were the first of those families to land, in the [views plan](./views.md); comments followed in the [comments plan](./comments.md), and extensions in the [extensions plan](./extensions.md). [#59](https://github.com/osama784/schemamill/issues/59) is the scoping slice its own body asks for; its frozen brief is the [first comment](https://github.com/osama784/schemamill/issues/59#issuecomment-6059861033), the live `pg_dump` capture is the [fact report](https://github.com/osama784/schemamill/issues/59#issuecomment-6059969056), and the [supply-pass promotion](https://github.com/osama784/schemamill/issues/59#issuecomment-6058718000) demanded explicit coverage of the families reserved in [constraints and indexes](./constraints-indexes.md) §Deferred. The anchors: [`core-domain.md`](../domain/core-domain.md) hard problem #1 — import fidelity is "the gate everything else waits behind" — [ADR 0004](../adr/0004-postgresql-only-dialect-seam.md), the [first slice](./first-slice.md) §Out, that §Deferred, and [#33](https://github.com/osama784/schemamill/issues/33)'s decomposition: "Next: views. Then: comments." — comments landed last, so they were modeled once. This plan is the long tail's map: every family below is owned by exactly one slice, A–L.

## Goal

Every object family a real `pg_dump` carries either has its own slice or a named deferral, and every fidelity trap inside a family is assigned to the slice that will fix it — no family and no trap falls silently between slices.

## Scope

**In:** the family inventory below; the twelve-slice decomposition A–L and the filing policy (A–F filed now, G–L named for a future supply pass); the named traps and their owners; and two standing rules — comments couple to views (#33) and each family slice carries its own comment surface from the day it models its family, so later families never re-litigate comments; privileges model tables and sequences first, with roles as opaque names, and ACLs on unmodeled families stay named skips until their family lands.

**Out, named — never silent:** beyond-inventory families — schemas as objects, foreign tables/servers, aggregates, operators, casts, collations as objects, event triggers, extended statistics, publications/subscriptions — each keeping its current skip-named behavior, itemized in §Deferred below; introspection parity, where [#76](https://github.com/osama784/schemamill/issues/76) (indexes), [#77](https://github.com/osama784/schemamill/issues/77) (column defaults and attributes), [#79](https://github.com/osama784/schemamill/issues/79) (constraints), and [#80](https://github.com/osama784/schemamill/issues/80) (sequences and identity columns) have shipped, leaving the remaining transport/streaming and CLI/studio surfaces under the [#71](https://github.com/osama784/schemamill/issues/71) umbrella; the import-side gap [#79](https://github.com/osama784/schemamill/issues/79) named — the parser reads `WITHOUT OVERLAPS`/`PERIOD` and not-null `NO INHERIT` while the importer dropped them silently — shipped in [#124](https://github.com/osama784/schemamill/issues/124), where each form is now flagged and dropped; comment introspection shipped for tables, columns, sequences, views, and materialized views in [#146](https://github.com/osama784/schemamill/issues/146) ([comments plan](./comments.md), [ADR 0026](../adr/0026-catalog-comment-reads.md)), and for constraint and index comments in [#192](https://github.com/osama784/schemamill/issues/192) ([ADR 0028](../adr/0028-catalog-constraint-and-index-comments.md)); data rows; and everything implementation-shaped — each slice's brief decides model shapes, and no ADR is due from this map.

**Deliberately shallow for now:** the `pg_dump` forms are exactly as the fact report records them (`[live-16]` on PostgreSQL 16.15; `[source-cited]` for 17/18 deltas), not re-derived; per-family model shapes are deferred to each slice's brief.

## Traps

Four fidelity traps sat in the import before #88; A fixed the two wording ones in #88, I owns the two partial-import ones.

**Diagnostic object naming ([#188](https://github.com/osama784/schemamill/issues/188)):** a diagnostic attached to a model entity names the schema-qualified identity of the owning entity as its object and leaves the member detail (index name, constraint label) in the message — `schema.name` for a table, sequence, view, or matview, `schema.index` for a named index (an unnamed index keeps its owning `schema.table`, because the source named no index), and `schema.table` for a constraint — with extensions (bare name, [ADR 0022](../adr/0022-extensions-travel-the-model.md)) and whole-object skip diagnostics (`COMMENT ON` targets and exclusion skips) as the named exceptions.

- **Matview mislabeled `CREATE TABLE AS`** — fixed in #88: `import.ts` discriminates `objtype` so a materialized view reads `CREATE MATERIALIZED VIEW` while `CREATE TABLE AS` keeps its bytes; since #89 the matview is imported rather than skipped, while the CTAS skip stays pinned by `names every long-tail family in dump order` and the matview import by `imports plain views and materialized views, sorted by identity`.
- **REVOKE mislabeled `GRANT statement`** — fixed in #88: `describeStatement` (`GrantStmt` branch), `import.ts:3895–3898` discriminates `is_grant`, so GRANT keeps `GRANT statement`/object `GRANT` and REVOKE reads `REVOKE statement`/object `REVOKE`; both REVOKE forms are pinned by `names every long-tail family in dump order` (`import.test.ts:546`, its REVOKE rows).
- **`LIKE` imports a zero-column table** — `import.ts:588–591` flags the clause and imports the table with none of the copied columns; the tag is never emitted by `pg_dump` (`[live-16]`). → I.
- **Inheritance and partitioning import partial tables** — `INHERITS` is flagged (`import.ts:1199`) and the child imports own-columns-only, matching the emitted `CREATE TABLE … INHERITS (…)` (`[live-16]`); a partitioned parent is flagged (`:1200`) and imports as a plain table. A hand-authored `PARTITION OF` child is skipped whole (`:523–533`); a `pg_dump` child arrives as a standalone `CREATE TABLE` and is imported once as a plain table, then its `ATTACH PARTITION` is skipped and named against the parent (`:2418–2420`) (`[live-16]`) — there is no ATTACH matcher, so the captured form is not modeled as a partition. Import and catalog disagree for partitioned databases (the catalog skips both parent and child); [#142](https://github.com/osama784/schemamill/issues/142) owns the model fix. → I.

## Deferred

- **Slices G–L** — named in §Slices; a future supply pass files them.

- **Beyond-inventory families** — schemas as objects (skip-named `CREATE SCHEMA …`, `describeStatement, import.ts:3792–3795`), foreign tables (skip-named `CREATE FOREIGN TABLE …`, `describeStatement, import.ts:3851–3854`, and now pinned by `names every long-tail family in dump order`, `import.test.ts:546`), and servers, user mappings, foreign data wrappers, aggregates, operators, casts, collations as objects, event triggers, extended statistics, publications/subscriptions, and roles (all generic fallbacks, `describeStatement, import.ts:3909–3910`); each needs its own slice before it can be modeled.

- **Rule wording collapses variants** — `CREATE RULE <name> ON <table>` does not distinguish `CREATE OR REPLACE RULE` from `CREATE RULE`, nor `DO ALSO`/`DO INSTEAD` from each other or from `DO NOTHING`; the node cannot tell the `DO … NOTHING` forms apart, so the wording claims none of them.
- **`SELECT … INTO`** — stays `SELECT statement` (skipped `SELECT statement`), never `pg_dump`-emitted, and a different node from `CREATE TABLE AS`.
- **Comment-object abbreviations** — resolved by C ([#87](https://github.com/osama784/schemamill/issues/87)): `alterObjectKind` spells `MATERIALIZED VIEW` and `FOREIGN TABLE`, and the modeled comment families no longer reach the skip description at all, so the `TABCONSTRAINT` abbreviation is unobservable; the remaining unmodeled families' stripped keywords (`SCHEMA`, `EXTENSION`, …) are their SQL spelling.
- **Catalog-side diagnostic grammar** — untouched: ADR 0011 and ADR 0016 pin the catalog read's grammar; this slice changed only dump-import wording.
- **`position` for mid-statement flags** — remains the statement start; the pins do not assert positions.
- **Introspection parity** — the long tail must reach the introspection families too; [#76](https://github.com/osama784/schemamill/issues/76) (indexes), [#77](https://github.com/osama784/schemamill/issues/77) (column defaults and attributes), [#79](https://github.com/osama784/schemamill/issues/79) (constraints), and [#80](https://github.com/osama784/schemamill/issues/80) (sequences and identity columns) have shipped, leaving the remaining transport/streaming and CLI/studio surfaces under [#71](https://github.com/osama784/schemamill/issues/71).
