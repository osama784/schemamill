# 0018 — Catalog sequences and identity columns round-trip through pg_depend

**Date/Status:** 2026-10-26 · accepted

**Context:** The introspection tracer ([#55](https://github.com/osama784/schemamill/issues/55), [ADR 0011](./0011-introspection-transport.md)) read tables, columns, and primary keys and flagged every other fact; the catalog has since gained indexes ([#76](https://github.com/osama784/schemamill/issues/76), [ADR 0014](./0014-catalog-index-canonicalization.md)), column defaults and attributes ([#77](https://github.com/osama784/schemamill/issues/77), [ADR 0015](./0015-column-attributes-travel-the-model.md)), and constraints ([#79](https://github.com/osama784/schemamill/issues/79), [ADR 0016](./0016-catalog-constraint-canonicalization.md)), leaving sequences and identity columns as the last unread family from [#60](https://github.com/osama784/schemamill/issues/60). The model already carried both shapes — a first-class `Sequence` with effective options and optional `ownedBy`, and `Column.identity` with generation mode, effective options, and an optional schema-qualified name — and the dump importer already read both from `CREATE SEQUENCE`/`ALTER SEQUENCE` and the identity DDL forms. Only the catalog side was missing: the mapper hard-coded `sequences: []` and flagged every `attidentity` column. The acceptance bar is [ADR 0011](./0011-introspection-transport.md)'s congruence: a database built from a model's own plan must introspect to a model the existing `diff` considers unchanged, and deep-equal (order-significant) to that database's dump import. That forces one read to produce both shapes without inventing a second representation or a catalog-only spelling.

**Decision:** The `SELECT` gains one required `sequences` payload section, read in one pass over every `relkind = 'S'` relation in the same schema scope as the tables read: `pg_class` and `pg_namespace` join `pg_sequence`, and `pg_depend` is `LEFT JOIN`ed on `classid = 'pg_class'::regclass`, `objid = <sequence oid>`, `objsubid = 0`, `refclassid = 'pg_class'::regclass`, `deptype IN ('a','i')`. The owner side is likewise all `LEFT JOIN`s — `pg_class`, `pg_namespace`, and `pg_attribute` on `attnum = refobjsubid AND NOT attisdropped` — so a standalone sequence carries nulls in every owner column and no row multiplies. Each row states `schema`, `name`, `dataType` (`format_type(seqtypid, NULL)`), the declared `start`, `increment`, `minValue`, `maxValue`, and `cache`, `cycle`, `persistence` (`relpersistence`), `ownerKind` (`deptype 'a'` mapped to `owned`, `'i'` to `identity`, null otherwise), and `ownerSchema`/`ownerTable`/`ownerColumn`. The section follows the existing `COALESCE(json_agg(…), '[]'::json)` convention, so a catalog with no sequences yields `[]`, not null.

The mapper partitions the rows; the dependency type is the partition key. A row with no dependency maps to a standalone `Sequence` with no `ownedBy`; a `deptype 'a'` row maps to a `Sequence` whose `ownedBy` is `{table: {schema, name}, column}` after the owner is validated; a `deptype 'i'` row is consumed into `Column.identity` and never appears in `Model.sequences`. Identity sequences are internal to a column — they are not `OWNED BY`, are not detachable, and the importer produces the same shape — so mapping them as ordinary sequences would create a duplicate fact and break deep-equality. Every value is passed explicitly through `effectiveSequence`/`effectiveIdentity`, so the catalog's effective options equal what the dump import resolves; ordinary sequences sort by `(schema, name)`, mirroring the importer's model order, sequence findings sort by the same key, and identity rows attach to their columns, whose order is the table read's. The mapper's result never depends on payload row order.

Identity attachment is total and fail-closed. Every mapped column with a non-empty `attidentity` requires exactly one `deptype 'i'` row owned by its `(table, attnum)`; the descriptor is built with the row's actual options, and its `sequenceName` is always the real internal sequence name. A missing attachment, a second internal sequence for one column, an internal sequence owned by a column without `attidentity`, an unknown `attidentity` letter, a non-integer identity column, a duplicate `(schema, name)` sequence row, an owned row with no owner table, and an owner column that an otherwise-read ordinary table does not carry are payload-contract throws. The name is not optional in practice: `pg_dump` always states `SEQUENCE NAME` for an identity column on PostgreSQL 10 and newer, so the importer always carries one, and the deep-equal bar requires the catalog to read it. The engine guarantees an identity sequence lives in the same schema as its table (`process_owned_by`: a sequence must be in the same schema as the table it is linked to), so the importer's cross-schema `SEQUENCE NAME` flag branch is defensive and dump-unreachable; the catalog reads the real, same-schema name. Nobody should "align" the readers by dropping the read name.

The `pg_sequence` values are 64-bit integers; `json_build_object` would encode them as JSON numbers and lose precision above `2^53` in JavaScript. Each numeric field is cast to `::text` in SQL and parsed as a string, then canonicalized by the existing effective-value rules; no JSON number is ever produced for an option. Unit fixtures pin both 64-bit bounds (`-9223372036854775808` and `9223372036854775807`), and a live scene carries a bigint sequence at `MAXVALUE 9223372036854775807` end to end. `seqstart` is the declared `START WITH`, not `last_value` and not the sequence's current state; stored state (`last_value`, `is_called`), `RESTART`, `setval`, dump-side `DROP SEQUENCE`, and sequence renames/`SET SCHEMA` stay outside the model.

Owner validation follows the flag/skip split [ADR 0011](./0011-introspection-transport.md) settled. A sequence whose owner is an unread relation — a partitioned parent, a view, a foreign table, or a dropped attribute (the importer's `process_owned_by` accepts `'r'`, `'f'`, `'v'`, and `'p'` owners) — is consumed with a `skip`, code `unsupported-statement`, object `<schema>.<name>`, and message `sequence <schema>.<name> belongs to unread relation <schema>.<table>; it is not represented`. It is not mapped and no identity is attached; a skip takes precedence over that row's persistence flag. A standalone fallback would invent an ownership fact, while a throw would turn a sane if unmodeled database into a transport failure; the plan contract assumes every `ownedBy` names a model table and column, so neither is acceptable. A named owner column missing from an otherwise-read ordinary table remains contract drift and throws.

Persistence is flagged, not modeled. No `Sequence` or `Identity` field is added. An ordinary sequence with `relpersistence` other than `p` still maps plain and carries an `unsupported-attribute` flag with object `<schema>.<name>` and the exact message `sequence <schema>.<name> is unlogged; unlogged sequence persistence is not represented yet` (or the `temporary` spelling); a temporary sequence cannot occur in the read schema scope (`pg_temp*` is excluded) but is named rather than silently impossible. An identity sequence whose persistence differs from its table's still attaches, and carries a flag whose object is the table (`<schema>.<table>`, the column-flag grammar) with the column named in the message: `column <column>'s identity sequence <schema>.<name> has unlogged|logged persistence; identity persistence is not represented yet`. This state is unit-pinned only, for two independent reasons: the live harness's `assertSequencesRetained` rejects any import diagnostic naming a sequence and `assertIdentitiesRetained` rejects any containing "identity", so a persistence scene would fail the retention guards before introspection; and for divergent identity persistence PostgreSQL 15+ `pg_dump` emits `ALTER SEQUENCE … SET LOGGED|UNLOGGED`, which the importer cannot read and skips with a sequence-naming diagnostic. Extending the harness guards is a scope change, not something this slice folds in silently.

The payload contract churns once: `expectFields(document, 'catalog payload', […])` gains `sequences` last, and `parseSequenceRow` mirrors the strict field list. `ownerKind` is `null` or one of two literals; a missing or unknown field, a wrong-typed row, an unknown `dataType`, and a duplicate `(schema, name)` throw. The unit suite centralizes every fixture through one `payload()` helper, so the churn is the helper/type plus the existing missing-field and unknown-field negative cases.

Diagnostics extend the existing order: table flags, then column flags (generation only now — the identity flag is removed, generation stays flagged), then not-null flags, constraint findings, index findings, and sequence/identity findings last, in `(schema, name)` order. `position` is never set. Sequence findings use the `<schema>.<name>` object; the identity-persistence flag uses `<schema>.<table>` and names the column and sequence in its message. The messages are pinned by tests and never localized. `matches-import` scenes must carry no such findings, and the flags pins are unit-level.

Extension members stay a named pre-existing residual: this read adds no `deptype = 'e'` filter. The tables, columns, constraints, and indexes reads already read extension-member objects that `pg_dump` excludes, so filtering only sequences would create a new asymmetry between families. The live scenes avoid extensions that create sequences or tables (`btree_gist` creates none), and the residual is recorded rather than hidden.

One blind spot is recorded, not fixed. The dump importer does not validate an `OWNED BY` owner (`import.ts:1169–1175`), so on a database where a sequence is owned by an unread relation `importDump` keeps a dangling `ownedBy` while the catalog reader skips the sequence and names it. No staged `matches-import` scene can see the disagreement, because the model cannot declare such an owner. Import-side owner validation is owed as a follow-up and is not folded into this slice.

The floor is PostgreSQL 13, matching the rest of the catalog read: `pg_sequence` exists there and its eight columns are identical through PostgreSQL 18, so no version negotiation is needed. Version gating and live server detection stay with [#57](https://github.com/osama784/schemamill/issues/57). This ADR does not supersede ADR 0011, 0014, 0015, or 0016; they stand as written.

**Consequences:** A database built from a model's own plan now introspects to a model the `diff` considers unchanged, and deep-equal to the dump import, for standalone and owned sequences with their effective options and ownership, and for identity columns with generation mode, effective options, and the real sequence name. The new `introspection-sequences-identity` scene pins a standalone sequence with non-default options and a bigint bound, an owned sequence, a `GENERATED ALWAYS` identity with a custom `SEQUENCE NAME`, a `GENERATED BY DEFAULT` bigint identity with defaults, and a `nextval(…)` default; `matches-import` is asserted on `serial-create`, `sequence-add-drop`, `sequence-alter`, `owner-drop-order`, `detached-drop`, `identity-to-sequence`, and `sequence-to-identity`. The identity flag disappears from `columnDiagnostics`; generation remains flagged. No core, CLI, plan, render, or workspace change is needed — the model and core normalization already existed — so this is a public read-capability change with one changelog entry. The persistence flags and the unread-owner skip are unit-pinned because their live staging is blocked by the harness guards and, for divergent identity persistence, by the importer's unread `SET LOGGED`/`SET UNLOGGED` dump statement.

**Deferred:** Sequence state (`RESTART`, `setval`, `last_value`, dump-side `DROP SEQUENCE`); sequence renames and `SET SCHEMA`; unlogged and temporary sequence persistence modeling; identity persistence modeling; partitioned-table identity reading (and sequences owned by unread relations beyond the named skip); extension-member filtering; a catalog-edited identity sequence whose type diverges from its column; live flags scenes for persistence (the retention-guard extension); import-side validation of `OWNED BY` owners (the dangling-`ownedBy` blind spot; a `factory:proposed` follow-up is filed at bookkeeping); CLI and studio consumption ([#71](https://github.com/osama784/schemamill/issues/71)/[#83](https://github.com/osama784/schemamill/issues/83)); version gating and server detection ([#57](https://github.com/osama784/schemamill/issues/57)); streaming and the client-library transport revisit ([#71](https://github.com/osama784/schemamill/issues/71)); and `pg_get_serial_sequence` (unused; the bulk `pg_depend` join is the read). The DDL-only identity scenes (`identityCreateScene`/`identityAlterScene`) gain no introspection assertion: the new scene covers those shapes, and a second assertion would duplicate coverage without a new state.
