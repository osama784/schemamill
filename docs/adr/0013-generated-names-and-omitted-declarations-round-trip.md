# 0013 — Generated names and omitted declarations round-trip

**Date/Status:** 2026-10-11 · accepted

**Context:** PostgreSQL does not store the name a statement wrote when it exceeds 63 bytes: `truncate_identifier` clips an explicit identifier at parse time with a notice, and a generated name — `makeObjectName`'s shrink loop over the table and column parts and the column-addition loop that assembles them — is truncated silently, so the name the catalog holds can differ from the formula schemamill predicted. The predictions were naive joins with no truncation, so import canonicalization and synthesized drops matched only the untruncated formula: a dump of a long-named unnamed member read as remove + add, and a drop rendered the assembled name, which PostgreSQL clipped to a different name and refused to drop — the pre-fix bug. [ADR 0009](./0009-render-refuses-duplicate-conventional-names.md)'s guard could not see two unnamed predictions that only collapse under truncation, a class it named as deferred. Separately, a foreign key declared without `referencedColumns` read as changed after apply, because a dump always states the list the declaration omitted. Slice A of the [render-refusal plan](../plans/render-refusal.md) ([#75](https://github.com/osama784/schemamill/issues/75)) needed the naming boundary mirrored faithfully and the omitted-list equivalence settled before the guard and the round trip could be trusted.

**Decision:** `names.ts` is the single prediction source and mirrors PostgreSQL's own naming rather than approximating it. `truncateIdentifier(name)` returns an explicit identifier's server form — the longest prefix of at most 63 UTF-8 bytes that never splits a character, the mirror of `truncate_identifier` and `pg_mbcliplen` under a UTF-8 database, and idempotent. `makeObjectName(name1, name2 | null, label)` mirrors the server's shrink exactly: the inputs are clipped first, because PostgreSQL passes stored names that are already at most 63 bytes; the longer part shrinks one byte at a time until the parts fit the available budget, a tie shrinking the second part; each part then clips at a character boundary; and the label is never truncated. The column part mirrors `ChooseIndexNameAddition` and `ChooseForeignKeyConstraintNameAddition`: parts join with underscores and the loop stops after the part that brings the running length to `NAMEDATALEN`. Every `synthesized*Name` is the mirror — `idx`, `key`, `pkey` with `name2 = null`, `fkey`, `check`, and `not_null` — so short inputs stay byte-identical to the earlier formulas and long inputs predict the stored name.

An explicit name renders as written; PostgreSQL clips it at parse time, and a hand-written name longer than 63 bytes is a pinned residual, not silently rewritten. A generated name renders in its server form, because a statement naming the assembled form would resolve a different object — the long-named unnamed drop the pre-fix renderer got wrong now names the object the catalog holds. Import canonicalization compares a dumped name against the same server form, so a generated name PostgreSQL truncated strips back to unnamed exactly as a short one does; collision-suffixed names (`_idx1`, `_key1`, …) stay named, because the server assigns them from catalog state that is not knowable offline, and the twin guards and the not-null merge are unchanged. The duplicate-name guard resolves index names through their server forms — an explicit name through `truncateIdentifier`, an unnamed prediction through the mirror — so two unnamed predictions that collapse, or a prediction against an explicit name equal to its server form, refuse with `RenderRefusalError`; a refusal message also shows an unnamed claimant's untruncated prediction when it differs from the collapsed server name, so the collapse is visible. This closes the truncation-collapse class ADR 0009 deferred; ADR 0009 stands as written, and the remaining guard namespaces stay with slice B.

A foreign key's `referencedColumns` compares through a comparison-side equivalence in `foreignKeysEqual`: both sides empty are equal regardless of the referenced table's key — the dependent-foreign-key synthesis owns primary-key moves; one side empty is equal to an explicit list exactly when that list equals the empty side's own model's referenced-table primary key, in primary-key order, and an absent referenced table or a table without a primary key leaves them unequal; two explicit lists compare element-wise. The equivalence replaces only the `referencedColumns` clause — name, referencing columns, referenced-table identity, referential actions, enforcement, and deferrability stay conjunct in every branch — and a resolved list never enters a payload, identity, or step: whole-model primary-key maps are threaded from `diff()` for the comparison alone. This is a deliberate widening of snapshot-diff equality ([ADR 0003](./0003-changes-are-snapshot-diffs.md)) for one field: an omission and the primary key its own model resolves are the same fact.

**Consequences:** A dump of a model-declared unnamed member whose generated name exceeds 63 bytes imports unnamed and round-trips to an empty diff; a long-named unnamed drop applies against the object PostgreSQL actually stored; a truncation collapse is refused loudly instead of rendered as SQL that fails at apply; and a foreign key declared without a referenced-column list round-trips against a dump that states the list. Output changes only for names longer than 63 bytes and the omitted-referenced-columns equivalence; short names stay byte-identical and no golden changes. The predictions assume a UTF-8 database encoding, and any other encoding is a named residual. Deferred, by name: slice B's remaining guard boundaries — constraint twins (same-kind and cross-kind), cross-table same-schema index names, the create-table and add-column claimants, baseline occupancy with the `renderSql` baseline parameter, the PostgreSQL 18 unnamed-not-null occupancy question, and refusal surfacing through the hazard channel with its own ADR; collision-suffix recovery from a live catalog (the [introspection follow-ups](../plans/introspection-attributes.md)); version gating across PostgreSQL majors; hand-written explicit names longer than 63 bytes; an omitted list whose referenced table is absent or has no primary key, or that matches a unique constraint rather than the primary key; exclusion constraints and expression, partial, or covering indexes ([#90](https://github.com/osama784/schemamill/issues/90)); and constraint-validation hazards (the [hazards plan](../plans/hazards.md)).
