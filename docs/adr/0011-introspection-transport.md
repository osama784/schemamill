# 0011 — Live introspection is a `psql` batch returning one JSON document

**Date/Status:** 2026-10-07 · accepted

**Context:** The `CatalogReader` seam ([`packages/core/src/seam.ts`](../../packages/core/src/seam.ts)) was declared with no implementation behind it; DDL import was the only inbound path, and the tracer slice ([#55](https://github.com/osama784/schemamill/issues/55)) needed a transport, a read shape, and a failure split before any catalog object family could be read. The choices bind every later family — indexes, constraints, sequences, identity — and no client library exists anywhere in the repo (`libpg-query` is a WASM parser), so adding one would be an approval-worthy dependency; the live harness already spawns `psql` and `pg_dump` from `PATH`.

**Decision:** `packages/postgres/src/catalog.ts` binds `catalogReader: CatalogReader<string, Model, Diagnostic>` — the connection type is the libpq connection URI string — and the transport is the `psql` binary, adding no client-library dependency: `psql -X -q -w -tA -v ON_ERROR_STOP=1 -d <url> -c "<one SELECT>"`, the child environment carrying `PGOPTIONS='-c search_path= -c default_transaction_read_only=on'`. A single `-c` batch is one simple-query message and therefore one implicit transaction, so the read is one snapshot: the `SELECT` returns one `json` document whose `tables`, `columns`, and `primaryKeys` sections are `json_agg`s (each `COALESCE`d to `'[]'`) built in that same snapshot, rather than three batches that could straddle a concurrent DDL change. `json`, not `jsonb`, keeps `row_to_json`'s key order.

The read-only guarantee is the read itself — the single `SELECT` — and `default_transaction_read_only=on` is posture, not the guarantee: PostgreSQL documents its read-only notion as high-level, forbidding `CREATE`/`ALTER`/`DROP` (temporary tables included) and non-temporary DML but still allowing DML against pre-existing temporary tables, so it "does not prevent all writes to disk". The child's empty `search_path` is the congruence with `pg_dump`, which reads the catalog under the same empty path, so `format_type`'s spelling for built-in types is byte-identical to the dumped DDL the importer reads. Every column and clause the `SELECT` uses exists in PostgreSQL 13 — `conparentid` since 11, `attgenerated` since 12, `attidentity` and `relispartition` since 10 — except `attcompression`, which exists only from 14; it is read through the row's `jsonb` form (`to_jsonb(attribute) ->> 'attcompression'`), so the statement parses on 13 and reports no explicit compression there. The harness's own floor is PostgreSQL 13 (`DROP DATABASE … FORCE`).

Failure handling splits at the payload contract: transport failures (spawn error, non-zero exit, unparseable JSON) and any violation of the `SELECT`'s own contract — a missing or wrong-typed field, an unknown field, an orphan or duplicate row — throw an `Error` carrying the reason, with the trimmed `psql` stderr when the exit is non-zero. Diagnostics are only for sane-but-deferred catalog state. A partitioned relation is skipped and named under `unsupported-statement` — a deliberate stretch of that code's name, since the relation rather than a statement is what goes unmapped; a new code would fork the diagnostic vocabulary before a second consumer exists. Unlogged or temporary persistence is flagged, and the column features the model does not carry — defaults, generation, identity, explicit collation, storage, compression — are flagged by cause, generated suppressing the default flag, in canonical table order with table-level flags before column flags and `position` never set. The mapper re-sorts tables by plain string comparison (SQL `ORDER BY` follows the database collation, which is not the model's ordering contract) and strips a primary key's name exactly when it equals `synthesizedPrimaryKeyName`, reusing `names.ts` — the same prediction the importer trusts.

The connection URI, including any password, travels as a `psql` argument and is visible in the process table to the same user, inherited from the live harness's precedent; a `.pgpass`/service-file or environment-based transport could remove that exposure and is deferred.

**Consequences:** Live introspection ships with no new dependency, one round trip, and a snapshot-consistent document whose contract fails loudly on drift instead of guessing; the model's canonical order is the mapper's, not the server's. Deferred, by name: indexes; constraints (unique, check, and foreign keys); sequences; identity-column reading; column-default reading (`pg_attrdef`/`pg_get_expr`); representation of unlogged/temporary persistence, explicit collations, storage, and compression; the ADR 0008 canonicalization debt (`CONCURRENTLY`, `USING INDEX`); version gating across PostgreSQL majors; a client-library transport revisit; large-catalog streaming; and the CLI/studio surface.
