# 0010 — The workspace is a hidden marker holding the committed model

**Date/Status:** 2026-10-07 · accepted

**Context:** The first slice of the workspace plan ([#54](https://github.com/osama784/schemamill/issues/54)) needed the container the studio and the CLI work within, and nothing workspace-related existed: no marker convention, no on-disk model, no `init`, and no production `node:fs` in core. A decision was needed on where a workspace lives on disk, how a starting path finds one, what creation refuses, what the model file may contain, and where the code sits — before any command can consume a workspace.

**Decision:** A workspace root is a directory containing a hidden `.schemamill/` directory, and the canonical model lives at `.schemamill/model.json` as bare model JSON (`{ "tables": [...], "sequences": [...] }`) with no wrapper and no version field. Hidden tool-managed directories (`.git/`, `.terraform/`) are the precedent for the marker; unlike `.terraform/` state, the model is the user's data and is meant to be committed, and the marker directory will later hold snapshots and caches. A `.schemamill` entry that is not a directory is `workspace-marker-invalid`, and a marker without a model is `workspace-model-missing`.

`resolveWorkspace(startPath)` resolves lexically with `path.resolve` and walks up by `dirname` to the fixed point (`dirname(dir) === dir`), with no `realpath` or symlink resolution; the nearest marker wins, and a corrupt nearest root is reported, never skipped over. Marker inspection distinguishes an absent marker (keep walking) from an unreadable one (`workspace-inaccessible`), so absence and inaccessibility are never conflated. `startPath` is required: core never calls `process.cwd()`, and the CLI passes its default `.` resolved against the process cwd.

`initWorkspace(targetPath)` refuses a target that is a file (`workspace-target-not-directory`), refuses an existing `.schemamill` entry — file or directory — with the repair hint `remove <target>/.schemamill to re-create it`, and refuses a target inside an existing workspace, naming that root (`workspace-inside-workspace`). Only ancestors are checked: a workspace containing another is allowed, because nearest-wins decides resolution. It claims the marker with an atomic `mkdir(<target>/.schemamill, { recursive: false })` and then writes the empty canonical model. A crash between the marker and the model leaves a marker without a model: `init` refuses it with the same repair hint, and resolution reports `workspace-model-missing`. A failed model write removes the just-created marker directory before reporting, best effort.

The reader parses with `JSON.parse`; a parse failure becomes `workspace-model-invalid` with the path and the V8 message appended verbatim as an opaque suffix (never parsed or relied on). Shape validation walks the payload recursively with a field→check table, fails closed on unknown keys at every level — including a top-level version — names the failing path (e.g. `tables[2].columns[0].type`), checks numeric sequence and identity options against the canonical integer string form `/^(0|-?[1-9][0-9]*)$/` (`cache` positive), and rebuilds the model by picking known fields, never `Object.assign`. The writer is internal — used by `init`, exported for tests only; a public writer is deferred — and emits entities rebuilt in `model.ts` declaration order with `undefined` optionals omitted, re-sorts `tables` and `sequences` canonically (schema then name, JavaScript string comparison) while nested arrays keep their stored order, and emits `JSON.stringify(value, null, 2)` plus a trailing newline. When a version envelope becomes necessary, the reader will accept bare and wrapped; today it fails closed on the unknown keys of a wrapped payload.

The module is `packages/core/src/workspace.ts`, using only `node:fs/promises` and `node:path` and staying dependency-free (ADR 0005). The CLI consumes it in `packages/cli/src/init.ts`: `schemamill init [path]` prints `Initialized workspace at <absolute path>` on stdout and exits 0, or `schemamill: <message>` on stderr and exits 1.

**Consequences:** A workspace is a plain, reviewable directory: the model is committed JSON, the marker is tool-managed, and `init` is safe to run twice or after a crash — both refusals name the repair. Resolution behavior is total: every marker state has a diagnostic, the nearest root wins even when corrupt, and no failure is silently skipped. Deferred, by name: consuming `resolveWorkspace` from `compare`/`plan` (including the `workspace-not-found` exit-1 mapping), a public writer API, snapshots and caches in the marker directory, studio consumption, multi-workspace handling, file-format versioning (bare accepted today, wrapped when the envelope changes), the `docs/architecture.md` persistence sync, EACCES refinement for init's ancestor check, Windows path edge cases, and a workspace usage-docs page.
