# 0015 — Column attributes travel the model

**Date/Status:** 2026-10-15 · accepted

**Context:** The introspection tracer ([#55](https://github.com/osama784/schemamill/issues/55), [ADR 0011](./0011-introspection-transport.md)) read tables, columns, and primary keys, and flagged every other fact it met — defaults, generation, identity, persistence, explicit collations, storage, and compression — because the model had nowhere to carry them; ADR 0011's deferred list named column-default reading (`pg_attrdef`/`pg_get_expr`) and the representation of unlogged/temporary persistence, explicit collations, storage, and compression. The column-attributes slice ([#77](https://github.com/osama784/schemamill/issues/77), [plan](../plans/introspection-attributes.md)) had to settle the model shapes and, more durably, the canonicalization rules: a live catalog reports effective state, not the DDL that produced it, so "explicit" had to be defined against the type's own defaults before import, diff, plan, and render could carry the attributes through the whole path. The importer's dump readings are the source of truth these fields must agree with, so the bar is congruence with what a dump says, not a recovery of what a hand-written target meant.

**Decision:** A column carries `collation` — opaque, whitespace-normalized text, absent meaning the type's default collation — plus `storage` (`plain`, `external`, `extended`, `main`) and `compression` (`pglz`, `lz4`), each absent meaning the type's default; a table carries `persistence` (`unlogged`), absent meaning `LOGGED`, PostgreSQL's default. The representation is explicit-only: the model states an attribute only when something stated it, and the absent state is the type's or server's default rather than a stored copy of it. Temporary persistence stays out of the model, so a temporary table keeps its flag.

The catalog read applies one canonicalization rule per field, and the rules are the reason the flags can disappear. A column's default is the `pg_get_expr(attrdef.adbin, attrdef.adrelid)` text, whitespace-normalized with the dump importer's `extractDefaultText` semantics, read only when `atthasdef` holds and a `pg_attrdef` row exists, and never for a generated column. An explicit collation is read as pg_dump's spelling — assembled in SQL as `format('%I.%I', nspname, collname)` over `pg_collation` and its namespace — exactly when `attcollation <> 0` and `attcollation <> typcollation`. Storage is the model word exactly when `attstorage <> typstorage`, with PostgreSQL's letters `p`/`e`/`x`/`m` mapping to `plain`/`external`/`extended`/`main`, and an unknown letter a payload-contract throw. Compression is `pglz` or `lz4` exactly when `attcompression <> ''`, read through the row's `jsonb` form so the statement parses on PostgreSQL 13 and reports no explicit method there. Persistence is `unlogged` exactly when `relpersistence` is `u`; `t` keeps its flag.

The congruence bar is ADR 0011's empty `search_path`, now exercised for the attribute reads: the read runs under the same empty path as `pg_dump`, so `pg_get_expr`'s default text and `format_type`'s type spellings are byte-identical to the dumped DDL the importer reads, and the collation assembly reproduces the qualified, quoted name pg_dump writes. A database built from a model's own plan therefore introspects to a model the existing `diff` considers unchanged, and deep-equal (order-significant) to that database's dump import; that dump-import congruence — not model-to-reimport identity — is the acceptance bar. The named residual is authored spelling: a hand-authored default text or collation spelling that differs from what a dump writes, and a storage method equal to the type's default (where `attstorage` equals `typstorage` and is indistinguishable from no explicit method), are stated by the model and rendered, but a re-dump cannot recover the distinction.

A rendered `ALTER TABLE … ALTER COLUMN … TYPE …` resets the column's collation, storage, and compression to the new type's defaults, so an `alter-column` step whose type or collation changed renders exactly one merged `ALTER TABLE <t> ALTER COLUMN <c> TYPE <type>[ COLLATE <collation>];` — both halves read from the step's target-side `attributes` carrier, so a type change restates an unchanged explicit collation and a collation removal renders the bare target type — and appends the target's explicit storage and compression as trailing `SET STORAGE`/`SET COMPRESSION` restatements, because the reset would otherwise drop them. With no type or collation change, a storage or compression field renders its own statement, and an absent target restores the default with `SET STORAGE DEFAULT` or `SET COMPRESSION default`. Every `SET STORAGE`/`SET COMPRESSION` statement — create tail, add tail, post-`TYPE` restatement, standalone — carries the dump's post-data `ALTER TABLE ONLY` form, matching pg_dump and keeping inheritance out of scope; only the merged `TYPE` statement stays bare. Create and add grammar states an explicit collation inline, after the type and before the constraints; inline `STORAGE`/`COMPRESSION` qualifiers are never rendered. Persistence renders as `CREATE UNLOGGED TABLE` and, for a change, a transactional `alter-persistence` step — table phase 13 — as `ALTER TABLE <t> SET UNLOGGED;` or, for the absent target, `SET LOGGED;`.

The version floors are stated, not negotiated: `SET STORAGE DEFAULT` needs PostgreSQL 16 and `SET COMPRESSION` needs 14, so a storage removal renders only on 16 and newer (the 13–15 residual is named); the inline `STORAGE` qualifier is PostgreSQL 18 grammar and is never rendered, following [ADR 0012](./0012-constraint-attributes-travel-the-model.md)'s doctrine that the renderer states as declared and negotiates no server version; and `attcompression` does not exist before 14, so the `jsonb` access reports no explicit compression on the 13 floor.

**Consequences:** A database built from a model's own plan introspects to a model the `diff` considers unchanged, and deep-equal to the dump import, for column defaults and for explicit collation, storage, compression, and unlogged persistence; the gated `column-attributes` scene (minServerMajor 16) pins the catalog values — default text, `attstorage` against `typstorage`, `attcompression`, the collation's OID against `typcollation`, and `relpersistence` — and both imports, and `introspection-flags` pins the covered flags gone. The covered flags disappear from the catalog read: generation and identity keep their flags, and temporary persistence keeps its, with the kept flags' wording and order byte-stable. ADR 0011's attribute deferrals are closed here — column-default reading and the representation of unlogged persistence, explicit collations, storage, and compression — except temporary persistence, and ADR 0011 stands as written, because accepted ADRs are immutable. The rules bind the later catalog reads: constraint introspection ([#79](https://github.com/osama784/schemamill/issues/79)) and sequence and identity reading ([#80](https://github.com/osama784/schemamill/issues/80)) rebase on this read and the importer's forms. Deferred, by name: identity-column reading ([#80](https://github.com/osama784/schemamill/issues/80)); temporary persistence; sequence persistence; statistics targets; storage parameters; typed tables and `ON COMMIT`; generated columns; persistence rewrite and lock hazards (the [hazards plan](../plans/hazards.md)); authored default and collation spelling drift, including a storage method equal to the type's default; storage removal below PostgreSQL 16; inline `STORAGE`/`COMPRESSION` rendering; CLI and studio consumption ([#71](https://github.com/osama784/schemamill/issues/71)); and version gating ([#57](https://github.com/osama784/schemamill/issues/57)).
