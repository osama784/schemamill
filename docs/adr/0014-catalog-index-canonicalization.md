# 0014 — Catalog index canonicalization: consumption, absence, and importer parity

**Date/Status:** 2026-10-11 · accepted

**Context:** [ADR 0008](./0008-index-concurrency-is-declaration-metadata.md) put `concurrently` on the modeled `Index` as apply metadata and named introspection's inability to recover the declaration as canonicalization debt: the catalog reports effective state, not the DDL that produced it, and `pg_dump` never emits `CONCURRENTLY` either. The dump importer had a consumption rule for `ALTER TABLE … ADD CONSTRAINT … UNIQUE USING INDEX` — the constraint takes the plain column-list index into itself — but a live catalog has no statement to read: the constraint and its index are separate rows, and a read that ignored `pg_constraint` would model a primary key's, unique constraint's, or exclusion constraint's index as a standalone `Index` the importer never produces, so a database built from a model's own plan would read back as changed. The introspection slice ([#76](https://github.com/osama784/schemamill/issues/76)) added an `indexes` section to the one read-only `psql` batch ([ADR 0011](./0011-introspection-transport.md)) for plain btree column-list indexes — named and unnamed, unique and plain — and the canonicalization rules needed to be settled once, because every later index-adjacent read inherits them and a wrong guess is a phantom diff.

**Decision:** The catalog read canonicalizes four ways, and both inbound paths stay congruent by construction.

Constraint-backed indexes are consumed by their constraints and never modeled standalone. The read joins `pg_constraint` with `pg_dump`'s constraint-join shape — `i.indexrelid = c.conindid`, `i.indrelid = c.conrelid`, `c.contype IN ('p','u','x')` — and excludes the matched rows; the `conrelid` guard is load-bearing, because a foreign key's `conindid` names an index on the referenced table rather than the constrained one. This is the catalog-side counterpart of the importer's `USING INDEX` consumption: a primary key's, unique constraint's, or exclusion constraint's index arrives through its constraint or not at all. Exclusion constraints are not modeled yet — their introspection is [#79](https://github.com/osama784/schemamill/issues/79) — but their indexes must not leak as a standalone index.

`concurrently` maps absent, always. The declaration is unrecoverable from the catalog and `pg_dump` never emits it, so both inbound paths agree: an index read from a live server is ordinary, and a flag-only difference between a baseline and a target stays no migration, exactly as ADR 0008's exclusion from structural identity requires. ADR 0008 stands as written; this closes the debt it named. The name side runs the importer's discipline: a stored name equal to `synthesizedIndexName`'s server form — `names.ts`'s mirror of `makeObjectName` with PostgreSQL's 63-byte truncation, the rule [ADR 0013](./0013-generated-names-and-omitted-declarations-round-trip.md) settled, which closed the truncation-collapse class [ADR 0009](./0009-render-refuses-duplicate-conventional-names.md) deferred — strips back to unnamed, collision-suffixed and mispredicted names stay named, and the importer's twin guard is kept for parity although a live catalog cannot reach it, since same-schema index names are unique.

Envelope and flag parity with the importer is structural. Every definition `pg_get_indexdef` produces is classified through `classifyIndexEnvelope`, the acceptance-rule function extracted from `translateCreateIndex` so both inbound paths run one source of truth: an expression element, partial `WHERE`, `INCLUDE`, a non-btree access method, non-default ordering or NULLS ordering, an operator class, a collation, storage parameters, `NULLS NOT DISTINCT`, exclusion operators, or an unusable element list skips the whole index — never a partial import — and the skip reuses the importer's reason wording in the catalog's fully qualified grammar, `skipped CREATE INDEX <schema>.<indexName> (<reason>)` with object `<schema>.<indexName>`. A row whose index is not `valid && ready` is excluded with a skip — `index <schema>.<indexName> is not valid and ready; invalid indexes are not represented yet` — mirroring `pg_dump`'s `indisvalid AND indisready` filter (`indislive` is ignored, as `pg_dump` ignores it). An index on a non-default tablespace is kept and flagged — `index <schema>.<indexName> is on tablespace <name>; tablespaces are not represented yet` — because the dump side imports the index plain and skips the `SET default_tablespace` statement, and introspection must not be silent about the unrepresentable state; `pg_get_indexdef` never emits a `TABLESPACE` clause, so the state is read from `reltablespace`, not the definition. Nothing is filtered silently, and contract drift is not canonicalized: an unknown field, a duplicate `(schema, indexName)` row — duplicates are schema-scoped, as PostgreSQL names indexes — an unknown or partitioned table, or a definition that does not parse to one `CREATE INDEX` throws.

Ordering is the importer's, not the server's. Rows sort by stored index name — plain string comparison, the per-table order `pg_dump`'s index read walks (`ORDER BY i.indrelid, indexname`) — the strip pass walks that order, and the result stable-sorts by `name ?? ''` exactly as `finalizeTable` sorts the importer's, so unnamed ties follow stored-name order in both paths and the mapper's output never depends on payload row order.

**Consequences:** A database built from a model's own plan now introspects to a model the `diff` considers unchanged for the plain btree column-list envelope, with the ADR 0008 debt paid rather than guessed; the gated `introspection-indexes` scene pins the round trip — constraint-backed exclusion, the tie order, a plain unique index, and a truncated-name strip — and the flags scenes pin the out-of-envelope wording, `NULLS NOT DISTINCT` on PostgreSQL 15 and newer included. The rules bind every later index-adjacent read: constraint introspection ([#79](https://github.com/osama784/schemamill/issues/79)) inherits the consumption rule and must consume the constraint-backed index end-to-end. Deferred, by name: expression, partial, and covering (`INCLUDE`) index modeling — named skips today; unique, check, and foreign-key constraint introspection ([#79](https://github.com/osama784/schemamill/issues/79)); `indisclustered`, `indisreplident`, and statistics targets (the importer skips those statements today); version gating across PostgreSQL majors ([#57](https://github.com/osama784/schemamill/issues/57)); tablespace and storage modeling; invalid-index and tablespace live staging, both needing server-owned state the harness cannot stage; and CLI/studio consumption.
