# 0040 — Post-data STORAGE and COMPRESSION rendering stands

**Date/Status:** 2026-11-25 · accepted

**Context:** [ADR 0015](./0015-column-attributes-travel-the-model.md) made a column's `storage` and `compression` travel the canonical model and chose to render them as post-data `ALTER TABLE ONLY … SET STORAGE` / `SET COMPRESSION` tails, never as inline create qualifiers (`:13`, `:15`). Its residual at `:11` is authored spelling drift, and `:17` names inline `STORAGE`/`COMPRESSION` rendering as the deferral. This ADR revisits that placement question — inline versus post-data — with a decision and a reason, without reversing ADR 0015.

The dispositive reason is new, not a restatement of ADR 0015's grammar or placement argument. The canonical model is explicit-only and carries no bit recording whether a stated attribute was authored inline or arrived through a post-data statement: `Column.storage` and `Column.compression` hold only the method word, absent meaning the type's default (`packages/core/src/model.ts:54-63`, `:171-177`). Import normalizes both spellings to those same fields — inline `STORAGE`/`COMPRESSION` qualifiers at `packages/postgres/src/import.ts:824-840` and post-data `ALTER COLUMN … SET STORAGE`/`SET COMPRESSION` at `:3136-3183` — and the catalog read reports effective state only (`packages/postgres/src/catalog.ts:1659-1679`). There is consequently no model state from which "render inline when the authored DDL expects it" could be decided: the request is unrepresentable without a model-shape change, which is outside this item. ADR 0015's `:13`/`:15` give the placement and the PostgreSQL 18 grammar of an inline `STORAGE` qualifier, but do not state this provenance fact.

The remaining force favors keeping the tail. [ADR 0012](./0012-constraint-attributes-travel-the-model.md)'s render-as-declared doctrine and `pg_dump`'s post-data emission are what make a database built from a model's own plan introspect to a `diff`-empty model; emitting an inline qualifier instead would break that dump round-trip congruence. Accepted ADRs are immutable (ADR README:5), so this correction is recorded in a new ADR rather than by rewriting ADR 0015, which stays accepted and byte-identical.

**Decision:** Explicit column storage and compression continue to render as post-data `ALTER TABLE ONLY … SET STORAGE` / `SET COMPRESSION` tails — on create and add tails, as post-`TYPE` restatements, and standalone. Rendering them inline is NOT adopted. ADR 0015 remains accepted and byte-identical; its placement decision is affirmed, not reversed.

The reason recorded here is the one ADR 0015 did not state: the model has no authored-inline-versus-post-data provenance bit, so an authorship-sensitive inline form cannot be selected from model state. Reversing this decision would require a fresh ADR (ADR README:5 immutability) together with a provenance bit on the model and target-version gating of an inline form; those are preconditions of any future reversal, not planned work in this slice.

**Consequences:** The named deferral class is closed with a reason, not marked shipped; there is no behavior, model-shape, import, catalog, render, or golden change. Existing unit and golden pins already cover the post-data placement and are load-bearing. No new `CONTEXT.md` headword is introduced; the existing Column and Introspection vocabulary covers the decision. ADR 0015, [ADR 0034](./0034-column-statistics-targets-travel-the-model.md), and [ADR 0039](./0039-markdown-export-projection.md) stay accepted and byte-identical; rollback is to delete this ADR and restore the one plan line.

**Supersedes:** [ADR 0015](./0015-column-attributes-travel-the-model.md):17's "inline `STORAGE`/`COMPRESSION` rendering" deferral, [the introspection-attributes plan](../plans/introspection-attributes.md):49's matching Deferred entry, and [ADR 0034](./0034-column-statistics-targets-travel-the-model.md):17's "inline `STORAGE`/`COMPRESSION` changes" deferral — exactly those three clauses, all CLOSED by this decision with the reason above, not shipped. ADR 0034's other deferrals stand untouched, as does the rest of ADR 0015 and the plan; neither accepted ADR is rewritten, and both stay byte-identical.
