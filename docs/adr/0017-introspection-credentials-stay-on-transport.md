# 0017 — Introspection credentials stay on the transport

**Date/Status:** 2026-10-23 · accepted

**Context:** [ADR 0011](./0011-introspection-transport.md) chose a single `psql` batch for live introspection, passed the connection URI on argv, and deferred a `.pgpass`/service-file/environment transport. The catalog reader ([ADR 0016](./0016-catalog-constraint-canonicalization.md)) and the live harness still follow that choice: `packages/postgres/src/catalog.ts` passes the full connection string to `psql -d`, and `live-pg.test.ts` passes its URLs positionally to `psql` and `pg_dump`. The spawned children inherit `process.env`, so `PGPASSWORD`/`PGPASSFILE` reach libpq whenever the caller's environment defines them, but this repository neither sets nor clears either variable. #86 asked whether the exposure should be closed now; #71 owns the transport revisit. Without a recorded posture, a partial credential fix can look like closure while leaving other argv paths open.

**Decision:** The introspection reader and the live harness keep the connection string on `psql`/`pg_dump` argv. Password-free connection URIs are the reader's supported posture: a password-bearing URI puts the secret on the process table, and the repo adds no credential mechanism of its own; a caller may supply libpq environment credentials at its own risk, since the repo neither strips nor manages `PGPASSWORD`/`PGPASSFILE`. A `.pgpass`/service-file/environment transport is **not** implemented here. It remains a transport-revisit item owned by [#71](https://github.com/osama784/schemamill/issues/71) — whose named bullet is "Client-library transport revisit" — now with an explicit pointer rather than an implied deferral. #71 also owns the live harness's argv exposure and keyword/value conninfo password stripping.

A partial fix is rejected: moving only URI passwords into `PGPASSWORD` inside `catalog.ts` would leave keyword/value conninfo strings — which libpq accepts in place of a URI — and the live harness's `psql`/`pg_dump` argv exposed, creating a false sense of closure. A real fix needs URI and conninfo parsing, percent-encoding round-trip tests, and harness cleanup; that is a transport change, not a credential patch.

This ADR does **not** supersede ADR 0011. Supersession here is whole-ADR only ([README](./README.md)), and 0011's transport decision stands unchanged; this record fixes the credential posture and names the deferred work. ADR 0011's text is not edited. The `psql -d` call site in `catalog.ts` carries a one-line pointer to this ADR and #71.

**Consequences:** Behavior is unchanged: the exposure ADR 0011 recorded remains, now bounded by a documented posture instead of an implied deferral. Residuals stay named — the live harness's `psql`/`pg_dump` argv, and keyword/value conninfo strings passed to the reader. Deferred, by name: `.pgpass`/service-file/environment transport; live-harness argv exposure; keyword/value conninfo password stripping — all [#71](https://github.com/osama784/schemamill/issues/71).
