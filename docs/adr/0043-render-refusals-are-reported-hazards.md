# 0043 — Render refusals are reported hazards

**Date/Status:** 2026-11-27 · accepted

**Context:** [ADR 0009](./0009-render-refuses-duplicate-conventional-names.md) made `renderSql` refuse two same-name index statements of one table and polarity, and named its boundary: index-only and plan-local. [ADR 0013](./0013-generated-names-and-omitted-declarations-round-trip.md) closed the truncation-collapse half of that boundary and deferred the rest — constraint twins, cross-table index names, the create-table and add-column claimants, baseline occupancy, the PostgreSQL 18 unnamed-not-null question, and surfacing through the hazard channel ([#102](https://github.com/osama784/schemamill/issues/102), slice B of the [render-refusal plan](../plans/render-refusal.md)). The original guard keyed `[owner.kind, schema, relation, polarity, name]`, so a table index and a materialized-view index of one schema with the same name both rendered; the two objects share PostgreSQL's schema-wide relation namespace, while constraint names are unique only per table. Primary keys, unique constraints, and exclusion constraints additionally claim the schema's index namespace with the constraint's name, and a cross-namespace coincidence between a constraint name and an index name is legal. A plan can also be individually sound yet unsatisfiable against a baseline it was not given: an explicit create can take a name an unnamed baseline object already occupies. Finally, a refusal was visible only as a stderr line from `plan`; `compare` reported hazards but never hit the guard, and [ADR 0027](./0027-plan-refuses-dangling-target-ownership.md) had deliberately rejected the hazard channel for a different, plan-time refusal. A decision was needed on the claim namespaces, the baseline contract, the version boundary, and how a refusal is reported without breaking the [ADR 0033](./0033-json-output-envelope.md) document.

**Decision:** `@schemamill/postgres` owns one pure claim collector (`name-claims.ts`), and both the render guard and the hazard analyzer derive their facts from it. Index claims span the schema: the key is `[schema, resolvedName, polarity]` across all four index step kinds on tables and materialized views, plus the backing indexes of primary-key, unique, and exclusion constraints, including create-table inline primary keys. Constraint claims are table-scoped and kind-agnostic: the key is `[schema, table, resolvedName, polarity]` across every add and drop constraint step — including named `add-not-null`/`drop-not-null` — and inline primary-key and not-null declarations. No object is claimed twice through separate steps, and polarity still lets a drop and a create of one name coexist. Guard resolution follows the server form: an unnamed claimant uses `names.ts`'s synthesized form, and an explicit claimant uses `truncateIdentifier`, because the guard reasons about the name PostgreSQL stores. Rendering still emits an explicit name as written; that divergence is a residual, not a silent rewrite. A collision is reported once, against the later claimant in plan order.

`renderSql(plan, options?)` gains an optional `baseline?: Model` beside `targetVersion`. "Occupied" means a materialized index or constraint in the baseline model minus same-identity drop-polarity claims in the plan, so a legitimate drop-then-recreate of one name still renders; `drop-table` releases its baseline indexes and constraints and `drop-column` releases the column's claims. At target 18 or newer an unnamed baseline not-null also releases its synthesized constraint name when its column or table is dropped. Without a baseline the guard stays plan-local and output is byte-identical to a call without the option; the full guarantee is scoped to callers that supply one. CLI `plan` passes its imported baseline, `export` passes the empty model because its create-only projection has no occupancy, and the live harness passes each scene's baseline. The `SqlRenderer.render(plan)` seam stays untouched.

PostgreSQL 18 materializes an unnamed `NOT NULL` as a table-scoped `pg_constraint` row named `<table>_<column>_not_null` (`ChooseConstraintName`, 53 bytes shared by table and column after the separators and the never-truncated label). At target 18 or newer the collector therefore reserves that name with a dedicated version-aware helper; below 18 an unnamed not-null claims nothing. The fact is version-dependent: it exists only when a target major reaches the renderer or the analyzer. To honor the issue's acceptance for `compare`, `compare --target-version <major>` takes the same validated 13–18 span as `plan`, and `HazardAnalyzer.analyze` gains an optional fourth `HazardAnalysisOptions` argument carrying `targetVersion`; existing three-argument callers remain valid and read the 13 default. Human `compare` reports the version-aware refusals. `compare --json` still emits no hazards, so [ADR 0033](./0033-json-output-envelope.md) stands and `schemaVersion` stays 1.

Core gains one `Hazard` kind, `render-refusal`, with one `HazardEntity` variant, `{ kind: 'name-collision', scope: 'index' | 'constraint', schema, table?, names: [earlier, later] }`; `step` is the index of the later colliding step. `analyzeHazards` emits it from the same collector the guard uses, so the report cannot drift from the refusal. Human `plan` keeps the plan display on stdout, the existing `schemamill: refusing to render …` stderr line, and exit 1; its hazard block now includes the refusal fact. Human `compare` includes the same block without rendering, and keeps the imported diagnostic exit code. `--json plan` gains the new hazard kind and entity keys in its document while keeping stderr, exit 1, and the envelope unchanged; `format.ts` and `json.ts` use exhaustive `assertNever` dispatch so a future kind fails the build. Cross-kind and cross-table collisions are pinned by unit tests, and the `name-collision` CLI golden pins the same-table hazard and refusal surface; the gated `baseline-index-occupancy` and PostgreSQL-18-only `unnamed-not-null-occupancy` scenes carry live evidence that the refused twin fails and the accepted plan applies.

**Consequences:** The model's intent still survives rendering — nothing is renamed, suppressed, or reordered. A plan that cannot express its names is both refused before any SQL is emitted and reported as a hazard wherever a plan or diff is shown. Output changes only for plans that actually collide: short, non-colliding plans render byte-identically, and callers without a baseline keep the old plan-local behavior (a deliberate degradation, recorded rather than claimed as a guarantee). Export supplies no occupancy, so the full baseline guarantee belongs to callers that have the starting model.

Named residuals: an explicit name longer than 63 bytes renders as written while the server stores its clip, so only the guard sees the server form; collision-suffixed names (`not_null1`, `_idx1`, …) depend on catalog state an offline plan cannot know; name prediction assumes a UTF-8 database encoding, and other encodings stay out of scope; an unnamed not-null claim exists only at a declared target of 18 or newer. No local PostgreSQL 18 server was available after the host move, so the version-specific scene is CI-gated. The corpus is 557 postgres tests + 61 scenes + 4 always-on live subtests = 622; the five PostgreSQL 18 scenes are floored. No local `SCHEMAMILL_TEST_PG_URL` was configured for this slice, so live pass/skip counts come from CI only.

**Amendment by correction, not supersession.** [ADR 0009](./0009-render-refuses-duplicate-conventional-names.md) remains accepted and unedited. Its `:7` decision that the guard considers same-table groups only, and its `:9` boundary that the check is index-only and plan-local, are narrowed here: index names are guarded schema-wide across tables and materialized views, constraint names are guarded table-scoped across kinds, and a supplied baseline participates in occupancy. The existing index message, stderr line, and exit 1 survive unchanged. [ADR 0013](./0013-generated-names-and-omitted-declarations-round-trip.md) remains accepted and unedited; its `:13` deferred list is narrowed here — the remaining guard namespaces, baseline occupancy, PostgreSQL 18 unnamed-not-null occupancy, and hazard surfacing are built by this decision, while collision-suffix recovery, non-UTF-8 encodings, and over-long explicit names stay deferred. [ADR 0024](./0024-synthesized-forms-consult-the-target-version.md) remains accepted and unedited; its `:11` v1 sentence "export renders creates only and compare renders nothing, so neither takes a flag in v1" is narrowed here: export consumed that deferral in [#178](https://github.com/osama784/schemamill/issues/178), and `compare --target-version` consumes it now through the version-aware analyzer, as recorded in the [target-version plan](../plans/target-version.md). The declaration-validation residual in that ADR is untouched.

[ADR 0027](./0027-plan-refuses-dangling-target-ownership.md)'s objection does not apply to this class. There the alternative was annotating a plan that would still emit an `OWNED BY` attach failing at apply — a caller ignoring hazards would fail anyway, and the check needed no dialect-specific knowledge, so it belonged in core beside `plan()`. Here the renderer itself refuses before emitting SQL: a caller ignoring hazards still gets no broken migration, and the claims, server-form names, and version boundary are dialect-specific facts owned by `@schemamill/postgres` beside the renderer. The plan-time ownership guard stays as ADR 0027 wrote it. [ADR 0033](./0033-json-output-envelope.md) also stands: adding an enumerated hazard kind is additive, compare's document projection is still the diff alone, and no `schemaVersion` bump is due.
