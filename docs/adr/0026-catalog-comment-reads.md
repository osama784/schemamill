# 0026 — Catalog comment reads

**Date/Status:** 2026-11-05 · accepted

**Context:** The canonical model has carried comments on tables, columns, sequences, and views since [#87](https://github.com/osama784/schemamill/issues/87) ([ADR 0021](./0021-comments-travel-the-model.md)), and views and materialized views since [#89](https://github.com/osama784/schemamill/issues/89) ([ADR 0019](./0019-views-and-materialized-views-travel-the-model.md)), but the live catalog read returned neither: its payload had no comment column anywhere and hard-coded `views: []`. A live-database import therefore lost every comment silently, and a database built from a model with views introspected back as a view-less model. ADR 0021 deferred catalog introspection of comments, and ADR 0019 deferred catalog parity and `matches-import` for views; [#146](https://github.com/osama784/schemamill/issues/146)'s promotion note split the work so this slice reads comments for the five comment-bearing families the catalog can reach, including the view read it needs, while constraint and index comments wait for slice 2. The accepted [ADR 0018](./0018-catalog-sequences-and-identity-columns.md) and [ADR 0019](./0019-views-and-materialized-views-travel-the-model.md) leave sequences and views as model entities the reader must return, so the contract to settle was how the catalog spells their comments and view bodies and how absence is represented.

**Decision:** The catalog read adds comments for tables, sequences, views, and materialized views through `obj_description(oid, 'pg_class')`, and for columns through `col_description(attrelid, attnum)`. A NULL comment means absent: the mapper omits the model key rather than attaching `comment: undefined`. Text is stored verbatim, matching the [ADR 0021](./0021-comments-travel-the-model.md) contract; an empty server comment is unreachable because PostgreSQL removes a comment on `IS ''` exactly as on `IS NULL`. Sequence comments attach only to the rows that become `Model.sequences` — standalone and owned sequences — after `effectiveSequence` computes their fixed shape; a comment on an identity row is ignored because `Identity` has no comment slot. No model, workspace, diff, plan, or render code changes: the model already carried every field.

The payload gains one `views` section after `sequences`, selected with `relkind IN ('v','m')` under the read's existing schema filters and ordered by schema then name. A row carries identity, `materialized = relkind = 'm'`, `definition`, `checkOption`, and `comment`. The definition is `pg_get_viewdef(relation.oid)` with exactly one trailing statement terminator stripped — the same shape `pg_dump` writes — normalized by the importer's `normalizeSourceText`, so both inbound paths produce the importer's canonical text; the mapper sorts rows with a `compareViewRows` that mirrors the importer's schema-then-name comparator, materialized kind not part of the key. `checkOption` decodes `pg_class.reloptions`'s `check_option=local` or `check_option=cascaded` and is absent otherwise. A materialized row carrying a check option throws instead of guessing, because PostgreSQL has no such object; the branch is server-unreachable and pinned directly, following the catalog's fail-closed contract.

**Consequences:** A live import now round-trips the five families' comments, and a model built from the catalog includes its views and materialized views for the first time. The `comment-introspection` live scene carries `matches-import`, so the catalog read must deep-equal the applied dump's import for views, materialized views, and every comment the read returns; the comparison remains same-server — both sides derive from the server's own deparse — so no cross-version `pg_get_viewdef` text is pinned. Because `pg_dump` writes `pg_get_viewdef` minus its terminator and the importer normalizes the body, the definition congruence needs no new model rule. ADR 0021's catalog deferral is partly closed and ADR 0019's catalog parity is partly closed, without editing either accepted ADR. The identity-sequence and view-column comment gaps stay named: neither has a model slot, so the importer may flag a hand-authored statement the catalog is silent about. The catalog also cannot reproduce the importer's flags for view reloptions and column lists — it returns the modeled view without them — and constraint and index comments stay unread, which is why `comment-round-trip` still declares no introspection assertion.

**Deferred:** Comments on constraints (primary, unique, check, and foreign key) and standalone indexes, and the `comment-round-trip` introspection assertion that waits on them — slice 2 of [#146](https://github.com/osama784/schemamill/issues/146); comments on identity sequences (no model slot); comments on view output columns (no model slot, [#143](https://github.com/osama784/schemamill/issues/143)); view reloptions and column lists beyond the check option, which import flags and the catalog does not reproduce; extension reads and extension comments ([#150](https://github.com/osama784/schemamill/issues/150)); non-UTF-8 database encodings; and refreshing comments from a live server without a full model import.
