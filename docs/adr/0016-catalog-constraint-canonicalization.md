# 0016 — Catalog constraint canonicalization

**Date/Status:** 2026-10-22 · accepted

**Context:** The introspection tracer ([#55](https://github.com/osama784/schemamill/issues/55), [ADR 0011](./0011-introspection-transport.md)) read tables, columns, and primary keys and deferred every other constraint fact; the indexes slice ([#76](https://github.com/osama784/schemamill/issues/76), [ADR 0014](./0014-catalog-index-canonicalization.md)) settled constraint-backed index consumption, and the constraint-attributes slice ([#74](https://github.com/osama784/schemamill/issues/74), [ADR 0012](./0012-constraint-attributes-travel-the-model.md), [ADR 0013](./0013-generated-names-and-omitted-declarations-round-trip.md)) put enforcement, deferrability, and the not-null name into the model and the dump importer. The constraints slice ([#79](https://github.com/osama784/schemamill/issues/79)) had to add the catalog side of that contract: unique, check, and foreign-key constraints, PostgreSQL 18's named not-null constraints, and a primary key's deferrability and period. The catalog reports effective state, not the DDL that produced it, so the acceptance bar is congruence with the dump importer — a database built from a model's own plan must introspect to a model the existing `diff` considers unchanged and deep-equal (order-significant) to that database's dump import — and every rule that makes the two inbound paths agree is recorded here once.

**Decision:** The `SELECT` gains a `constraints` section and a `notNullConstraints` section, and the existing `primaryKeys` rows gain `deferrable`, `deferred`, and `period`. All sections are required in the payload; `constraints` and `notNullConstraints` are always present, as empty arrays when the server has none (`notNullConstraints` is empty before PostgreSQL 18), and a missing or wrong-typed section is a contract throw. Both reads are table-scoped: `conrelid <> 0`, `conislocal`, `conparentid = 0`, `relkind = 'r'`, `NOT relispartition`, and the tables section's namespace exclusions; `constraints` selects `contype IN ('u','c','f','x')` and `notNullConstraints` selects `contype = 'n'`, joining the not-null row's `conkey[1]` to a non-dropped attribute. `constraints` rows are uniform — every key is emitted and the keys a kind does not use are `null` — with `schema`, `tableName`, `conname`, `kind` (`unique`, `check`, `foreign-key`, or `exclusion`), `columns`, `expression`, `referencedSchema`, `referencedTable`, `referencedColumns`, `onUpdate`, `onDelete`, `matchType`, `deleteSetColumnList`, `deferrable`, `deferred`, `validated`, `enforced`, `noInherit`, `nullsNotDistinct`, `including`, and `period`. `notNullConstraints` rows carry `schema`, `tableName`, `columnName`, `conname`, `validated`, and `noInherit`. A uniform row without a per-kind check would fail on every live read of an irrelevant key, so the mapper enforces a per-kind non-null matrix, not per-kind field sets. `unique` requires `columns`, `deferrable`, `deferred`, `validated`, `nullsNotDistinct`, `including`, and `period`; `validated` is read only for the defensive `NOT VALID` flag. `check` requires `expression`, `validated`, `enforced`, and `noInherit`; its deferrability pair may be present or `null`, because it too exists only for a defensive diagnostic. `foreign-key` requires `columns`, `referencedSchema`, `referencedTable`, `referencedColumns`, `onUpdate`, `onDelete`, `matchType`, `deleteSetColumnList`, `deferrable`, `deferred`, `validated`, `enforced`, and `period`. `exclusion` carries identity only, every other key `null`. A required key that is `null`, or a key outside the kind's read set that is non-null, throws. Every row is parsed fail-closed, and contract drift throws rather than canonicalizes: an unknown kind or field, a constraint or not-null row on an unknown or partitioned table, a not-null row naming a column the table does not carry, a not-null row on a column whose column row is not `NOT NULL`, a duplicate `(schema, table, conname)`, a duplicate not-null row for one column, and primary-key rows of one key that disagree on their deferrability or period.

Constraint-backed indexes stay consumed by the existing join — `i.indexrelid = c.conindid`, `i.indrelid = c.conrelid`, `c.contype IN ('p','u','x')` — inherited from [ADR 0014](./0014-catalog-index-canonicalization.md); the new constraint rows never re-model an index. ADR 0014 called the `conrelid` guard load-bearing because a foreign key's `conindid` names an index on the referenced table; that reasoning holds for a cross-table foreign key, but the correction is recorded here: while `contype` excludes `'f'`, the `conrelid` guard is behavior-preserving, the `contype` filter does the work, and `conrelid` is a planner aid. A self-referencing foreign key is the case that separates them — its `conindid` is an index on the same table, so dropping only `contype` would consume that index, while dropping only `conrelid` stays behavior-preserving; the `introspection-constraints` scene pins the `contype` filter through exactly that self-reference. Accepted ADRs are immutable, so ADR 0014 stands as written and this paragraph is the correction. `USING INDEX` provenance stays unrecoverable: the catalog shows an ordinary unique constraint named after the index, the same model both inbound paths converge on.

A check's `expression` is `pg_get_expr(c.conbin, c.conrelid)` passed through the importer's `normalizeSourceText`. For a table check's `CHECK (…)` clause, `pg_get_constraintdef` wraps exactly `pg_get_expr`'s text, and pg_dump's dump is the source of the importer's inner text, so normalizing both sides makes the strings equal; the child process already forces `search_path=''`, so the deparse is schema-qualified and deterministic, and GUC-sensitive constants are read from the same server as the dump, so per-server congruence holds; the model keeps the deparsed inner text verbatim — render re-adds `CHECK (…)`. The residual is authored spelling: deparse rewrites `CAST(x AS t)` to `x::t`, so hand-authored DDL can drift from the catalog on one server even though the dump-import path is congruent because pg_dump deparses too. Cross-major deparse drift stays with version gating ([#57](https://github.com/osama784/schemamill/issues/57)), and the probe battery is pinned to deparse-congruent spellings.

Names run the importer's discipline and twin guards. A stored primary-key name equal to `synthesizedPrimaryKeyName`'s server form strips back to unnamed; a unique, check, or foreign-key name strips when it equals its `synthesized*Name` server form and no entry with the same structure key is already unnamed or was stripped earlier; a not-null name strips when it equals `synthesizedNotNullName`. Collision-suffixed names and names outside the formula stay named, and `names.ts` handles 63-byte truncation. The importer's `uniqueConstraintStructureKey`, `checkConstraintStructureKey`, and `foreignKeyStructureKey` are exported and run through the same pre-scan and strip order, per table. A live catalog cannot stage a twin — per-relation `conname` uniqueness rules it out — but the guard is kept for parity with the importer and pinned by a direct unit fixture, the ADR 0014 precedent; the primary key needs no twin guard because PostgreSQL allows one per table.

Attributes map to the model's existing fields. Enforcement is the three reachable catalog states: `(validated, enforced)` of `(true, true)` is absent, `(false, true)` is `not-valid`, and `(false, false)` is `not-enforced`; `NOT VALID NOT ENFORCED` collapses to `not-enforced` because the server forces it, and `(true, false)` — validated but not enforced — is unreachable and throws. `conenforced` is read through `to_jsonb` and coerces `true` before PostgreSQL 18. Primary-key, unique, and foreign-key deferrability come from `condeferrable`/`condeferred`, with `INITIALLY DEFERRED` implying deferrable. Foreign-key actions map through the importer's `referentialAction` letters, the delete-column list is `confdelsetcols` (PostgreSQL 15, read through `to_jsonb`), and `referencedColumns` is always explicit from `confkey` — the model's omission equivalence handles an authored model that leaves the list out. A unique constraint's `nullsNotDistinct` and `including` come from the backing `pg_index` row (`indnullsnotdistinct`, PostgreSQL 15, read through `to_jsonb`; and `indnatts > indnkeyatts`), joined on `conindid`: neither `connullsnotdistinct` nor `conincluding` exists in any PostgreSQL release. `connoinherit` is not a unique or foreign-key signal — it is `true` for ordinary index-backed unique and primary-key constraints as well — so the read takes it only for checks and not-null constraints.

Temporal and not-null flags are new catalog grammar. `conperiod` (PostgreSQL 18, coalesced `false`) marks a primary key's or unique constraint's `WITHOUT OVERLAPS`, and a foreign key's `PERIOD`; `conenforced` and `conperiod` are read through `to_jsonb` so the statement parses on the PostgreSQL 13 floor. The model has no temporal field, so the catalog flags and drops them: `dropped WITHOUT OVERLAPS on primary key <name> from <schema>.<table>` and the unique form, and `dropped PERIOD on foreign key <name> …`. This is catalog-new grammar, not a catalog-only representation of modeled state: libpg-query's PostgreSQL 18 grammar parses `without_overlaps`, `fk_with_period`, and `pk_with_period`, and the importer silently drops all three today; not-null `NO INHERIT` is dropped silently there too. A follow-up is proposed to make the import path flag those states rather than drop them silently. A not-null constraint's `NOT VALID` and `NO INHERIT` are flagged and dropped with their representable not-null fact kept. Not-null `NOT ENFORCED` is unreachable — the grammar rejects it for `NOT NULL`, and `conenforced` is always `true` for `contype = 'n'` — and is recorded here rather than modeled. An exclusion constraint has no model shape and is skipped whole: `kind: 'skip'`, `code: 'unsupported-statement'`, object `<schema>.<conname>`, message `skipped exclusion constraint <schema>.<conname>`. The catalog cannot distinguish an inline declaration from `ALTER TABLE … ADD CONSTRAINT`, so it uses the whole-object skip grammar; the importer's existing forms differ (an inline exclusion flag-drop and an `ADD` statement skip), and the divergence is named, not hidden.

Diagnostics follow the import module's grammar and a pinned order: table-level flags, then column flags, then not-null flags in column attribute order, then constraint findings in stored `conname` order, then index findings in stored index-name order. `position` is never set. The flag lines are `dropped <attribute> on <kind> <conname> from <schema>.<table>` for unique `NULLS NOT DISTINCT`, `INCLUDE`, `WITHOUT OVERLAPS`, and the defensive `NOT VALID`; check `NO INHERIT` and the defensive deferrability; foreign-key `MATCH FULL`, `MATCH PARTIAL`, column list, and `PERIOD`; primary-key `WITHOUT OVERLAPS`; and not-null `NOT VALID` and `NO INHERIT`. Constraint rows are ordered by stored `conname` and not-null rows by table then `attnum`; the mapper then imposes the model's canonical order from core's doctrine. Payload row order must not affect the result — constraint rows sort by stored `conname` before canonicalization, and not-null rows attach by column name, so neither ordering can decide — and a shuffled-fixture test pins it.

Three exclusions are deliberate and silent, named here instead of diagnosed: domain constraints (`conrelid = 0`), constraint triggers (`contype = 't'`), and inherited copies (`conislocal = false`, with `conparentid = 0` narrowing partition clones). The read is table-scoped and the model carries none of them. One residual gap remains one-way: the importer flags `NO INHERIT` on a unique constraint, while the catalog cannot distinguish it from the `connoinherit = true` every ordinary index-backed unique constraint carries, so the catalog does not diagnose it. This is also the reconciliation of `constraint-attributes.md:42`: one named not-null constraint per column is server-enforced — PostgreSQL keeps at most one `contype = 'n'` row per column, and pg_dump aborts on a catalog-edited duplicate — so the catalog read throws on a duplicate rather than inventing a merge, while the model's first-name flag behavior stands for dump text, where hand-authored DDL can state several. The catalog cannot stage that case.

**Consequences:** A database built from a model's own plan now introspects to a model the `diff` considers unchanged, and deep-equal to the dump import, for unique, check, and foreign-key constraints, a primary key's deferrability, and PostgreSQL 18's named not-null constraints; the representable constraint attributes disappear from the flags, and the unrepresentable ones keep named diagnostics. The gated suite pins it: `introspection-constraints` (named, unnamed, composite, and deferrable unique constraints, the check-expression battery, composite and self-referencing foreign keys — including foreign keys whose referenced columns are a standalone unique index, the same-table one catching a dropped `contype` filter — every non-default referential action, deferrability, and `NOT VALID` on a check and a foreign key), the constraint flag scenes `introspection-flags-constraints`, `introspection-flags-constraints-15`, and `introspection-flags-constraints-18`, and `matches-import` assertions on `constraint-attributes` and `not-null-constraint-names`. On PostgreSQL 16.15 the suite is 315 tests across 45 scenes, 3 skipped — the PostgreSQL 18 scenes, skipped by name — and all 45 run on the CI's PostgreSQL 18. Deferred, by name: exclusion-constraint modeling; temporal (`WITHOUT OVERLAPS`/`PERIOD`) modeling; not-null `NO INHERIT` inheritance; domain constraints, constraint triggers, and inherited/partition constraint copies; `USING INDEX` provenance; `ON UPDATE … SET NULL (cols)` representation; unique and foreign-key `NO INHERIT` catalog detection (the one-way diagnostic gap); authored check-expression spelling drift (hand-authored DDL versus deparse on one server — dump import is congruent); import-side temporal and not-null silent drops (follow-up proposed); cross-major deparse drift and version gating ([#57](https://github.com/osama784/schemamill/issues/57)); CLI and studio consumption ([#71](https://github.com/osama784/schemamill/issues/71)); sequences and identity ([#80](https://github.com/osama784/schemamill/issues/80)); constraint-validation hazards ([hazards plan](../plans/hazards.md)); and expression, partial, and covering index modeling.
