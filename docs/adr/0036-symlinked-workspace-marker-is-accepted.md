# 0036 — A symlinked workspace marker is accepted

**Date/Status:** 2026-11-24 · accepted

**Context:** [ADR 0010](./0010-workspace-container.md) settled that a workspace root holds a hidden `.schemamill/` marker and that resolution walks up from a start path, returning the lexical directory that holds the nearest marker. Its statement at :9 that resolution uses `path.resolve` with "no `realpath` or symlink resolution" is about path canonicalization — the resolver reports the lexical root, never a resolved real path — and does not say what happens when the `.schemamill` entry itself is a symlink to a directory. The resolver only inspects the marker (`stat` plus an `isDirectory` check); it never reads through it directly, so a marker symlinked to a real workspace is a reachable shape that needed an explicit disposition and a test pin rather than an implicit side effect of `stat`.

**Decision:** A `.schemamill` entry that is a symlink to a directory is accepted as a valid marker. `findWorkspaceRoot` calls `stat` on the marker, which follows the symlink, and checks `isDirectory()` on the target; a symlink to a directory therefore succeeds and the walk stops there. The root returned stays the lexical directory containing the marker symlink — the resolver never calls `realpath`, so no path canonicalization is introduced and [ADR 0010](./0010-workspace-container.md):9 remains true as written. A marker whose target is not a directory keeps the existing `workspace-marker-invalid` failure. This records and pins behavior already present in `packages/core/src/workspace.ts`; no production change is made here.

**Consequences:** No new surface: no model, diff, plan, render, CLI, or golden byte changes, and accepted ADRs are untouched — this ADR adds a decision beside ADR 0010 rather than amending it, and carries no `Supersedes` or `Corrects` stanza. `packages/core/src/workspace.test.ts` pins the shape: it writes a canonical model into a distinct sibling `real/` directory with the model-taking init helper, symlinks `real/.schemamill` to `<root>/.schemamill`, and asserts that `resolveWorkspace(root)` succeeds with `root` equal to the lexical directory and a model deep-equal to the canonical model written. Hosts without symlink privilege (`ENOSYS`, `EPERM`, `EACCES`, `EXDEV`) skip that test; CI Linux exercises it.
