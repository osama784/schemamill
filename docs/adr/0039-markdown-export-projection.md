# 0039 — Markdown export projection

**Date/Status:** 2026-11-25 · accepted

**Context:** [ADR 0023](./0023-export-projects-the-model.md) made `schemamill export` a read-only projection of the canonical model with two formats, `ddl` and `json`, and deliberately named markdown as out of scope at `:7`. [#177](https://github.com/osama784/schemamill/issues/177) asked for a third, `export --format markdown`: a deterministic, readable document a human can review in a diff, without changing the workspace or a database. The canonical model is the only source of truth, so the new format must not become a second canonical form or acquire a round-trip back into a model. [The export plan](../plans/export.md) carried the original two-format contract and two markdown deferrals at `:15` and `:43`. ADR 0023 is accepted and immutable, so the narrow correction belongs in a new ADR rather than in an edit to that record.

**Decision:** `schemamill export --format markdown` prints a pure Markdown projection rendered by `renderMarkdown(model: Model): string` in a dependency-free `packages/cli/src/markdown.ts` module — no I/O, clock, filesystem, locale, or environment reads. The renderer sorts every collection itself, because the workspace reader preserves file order for nested arrays: tables, sequences, and views by `schema` then `name`; extensions by `name`; table and materialized-view indexes by `opt(name)`, `unique` (false before true), then `arr(columns)`; unique constraints by `arr(columns)` then `opt(name)`; check constraints by `expression` then `opt(name)`; foreign keys by `arr(columns)`, referenced table, `opt(name)`, referenced columns, and the optionals. Each comparator ends in a plain string comparison of `JSON.stringify(entry)` as a total tiebreak; table columns keep source order because ordinal is part of a table's shape. Section order is `# Schema`, then `## Tables`, `## Sequences`, `## Views`, and `## Extensions`, with empty collections omitted and an empty model rendering exactly `# Schema\n`. `fmt` spells absent as `(none)` (never fenced), booleans as `yes`/`no`, numbers as plain decimals, strings as code spans, and string arrays as comma-space joined code spans in parentheses; a code span uses a fence of `1 + longest backtick run` ticks with one space inside when the value starts or ends with a backtick, and backslash is literal. CRLF and lone CR fold to LF, every LF becomes `<br>`, tabs become `\t`, and all other C0 controls, DEL, and C1 controls become `\uXXXX` with uppercase hex (NUL via the U+0000 escape, never a raw NUL), with exactly one final LF. Every heading is followed by exactly one blank line, bullets are contiguous, adjacent entity blocks are separated by one blank line, nested bullets are indented two spaces, optional attribute bullets are omitted when absent, and attribute lines carry no trailing punctuation. All eleven comment slots appear: `comment` on tables, columns, primary keys, unique/check/foreign-key constraints, indexes, sequences, views, and extensions, plus `Column.notNullComment`. The `ddl` and `json` artifact bytes and their exit behavior stay byte-identical; the help/usage description, the `--format` option line, and the validation error string are deliberately re-pinned for the new value, and the `planOrReport` gate still validates a model before the format branch. This is a projection, not a second canonical format, and no import or round-trip is introduced. [The export plan](../plans/export.md) carries the byte-exact comparator list, escaping rules, entity templates, block layout, and worked byte example.

**Consequences:** A schema can now be read as a reviewable document without applying anything, and deterministic ordering and escaping make golden tests and PR diffs meaningful; the DDL and JSON artifacts, their goldens, and their exit behavior are untouched. The renderer is a new manual surface: it must sort what the workspace does not and escape every string before it reaches a code span, so shuffled-input and escaping batteries are load-bearing. `mutation:core` covers `packages/core` only, so all mutation evidence for this projection is manual adversarial checks in a scratch copy, not a harness extension. Adding a future model family requires updating four arrays and the renderer by hand — a named residual. Deferred by name: markdown for diffs/plans, docs-site integration, HTML, custom templates, round-trip / markdown-to-model import, a second canonical format, and extending the mutation harness to CLI (which would need a new runner or dependency and an owner decision). No new CONTEXT headword is introduced; ADR 0023 is immutable and stays byte-identical.

**Supersedes:** [ADR 0023](./0023-export-projects-the-model.md):7's "markdown stays out" clause — the full clause names `--out`, a header, markdown, a JSON envelope, schema drops, and schema ownership/ACL/comments as things that "stay out and are named deferred"; markdown is now a third supported projection, while the other deferrals stand. [The export plan](../plans/export.md):15's "Out, named" entry `markdown/docs projection` and :43's Deferred entry `markdown projection` are closed by [#177](https://github.com/osama784/schemamill/issues/177). The rest of ADR 0023 and the plan's other deferrals are unchanged; neither accepted ADR is rewritten, and ADR 0023 stays byte-identical.
