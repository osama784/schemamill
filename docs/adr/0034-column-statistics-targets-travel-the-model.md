# 0034 — Column statistics targets travel the model

**Date/Status:** 2026-11-23 · accepted

**Context:** A column's PostgreSQL statistics target — `pg_attribute.attstattarget`, declared in a dump as a post-data `ALTER TABLE … ALTER COLUMN … SET STATISTICS` — was read by neither path: the dump importer skipped the statement under the generic `AT_SetStatistics` fallback, and the catalog read did not select the column. [#204](https://github.com/osama784/schemamill/issues/204) closes those two deferrals end to end. Three server facts shaped the decision. First, the stored range is the integers 0–10000 inclusive: `0` means "no statistics" and is a real state, and the server clamps larger values with a WARNING, so the model rejects out-of-range values deterministically rather than inheriting the clamp. Second, the *default* has two physical spellings: `-1` on PostgreSQL 13–17 and SQL `NULL` on PostgreSQL 18, and `pg_dump` emits a numeric target only for non-default values on 13/16/18 — never `SET STATISTICS DEFAULT`. Third, `TYPE` preserves `attstattarget` (the docs' "statistics removed" is `pg_statistic` rows), so a type change cannot silently clear a stated target. The pinned parser carries the value in `command.def.Integer.ival`, with absent `def` meaning `SET STATISTICS DEFAULT`; there is no `num` field at runtime.

**Decision:** `Column.statisticsTarget?: number` holds an explicit integer target in the inclusive range 0–10000; absent means the server default. Existing models stay byte-identical. Canonicalization is one-way toward absence: a dump's `-1` and `SET STATISTICS DEFAULT` map to absent, the catalog's `-1` (13–17) and `NULL` (18) map to absent, and `0` is carried verbatim — no truthiness check anywhere on the new path. `ColumnRow.attstattarget` is `number | null`, read by a nullable-integer validator, so a PostgreSQL 18 row fails closed only on a genuinely non-integer value; a PG18-shaped row fixture pins that contract in the unit suite.

A field change to absent renders the universal reset `ALTER TABLE ONLY <t> ALTER COLUMN <c> SET STATISTICS -1;`, which every server from 13 through 18 accepts (`-1` is obsolete but still accepted from 17). No version floor is introduced. Emitting `SET STATISTICS DEFAULT` instead would require a PostgreSQL 17 floor under [ADR 0024](./0024-synthesized-forms-consult-the-target-version.md), so it is named as a deferral and not done. On create and add, a stated target renders as a post-data `SET STATISTICS` tail after `SET STORAGE` and `SET COMPRESSION`; on an `alter-column` step the target is restated after a merged `TYPE` statement, and a type-only change with a stated target keeps that target. No new step kind is added: the step union stays 34 kinds, 32 transactional and 2 non-transactional across 18 table phases, with `alter-column` remaining transactional in table phase 11.

This is a public core type change: `packages/core/src/index.ts` re-exports `Column`, `ColumnFieldChange`, `ColumnAttributes`, and the plan payloads, so adding members to those types breaks downstream exhaustive `never` switches. Every internal exhaustive site is updated, and the single `[Unreleased] › Added` changelog bullet carries the disclosure of the added core types; no second `› Changed` bullet is added.

Rollback has exactly one recorded decision: reverting this code explicitly requires stripping `statisticsTarget` from any authored workspace first, because the fail-closed workspace reader (`workspace.ts:719-721`) rejects the now-unknown key. No automated strip tool is added — that would be a new release and rollback surface outside this slice.

**Consequences:** A database built from a model's own plan introspects to a model the `diff` considers unchanged, deep-equal to the applied dump's import, for every carried target state. The `statistics-targets` live scene is floored at **13** so the PostgreSQL 13 `-1` path and the PostgreSQL 18 `NULL` path both run in CI; its six cases — stated target, server default, reset to absent, target `0`, type-only preservation, and type-and-target together — each pin the physical `attstattarget` (PG18 NULL normalized to `-1` in the check SQL), the rendered SQL golden, both imports, and the `matches-import` congruence. The local PostgreSQL 16.2 run reports 531 tests, 527 pass and 4 skipped, with the scene green; CI's `verify-postgres` matrix covers PostgreSQL 13 and 18.

`SET STATISTICS` takes a `SHARE UPDATE EXCLUSIVE` lock. That cost is a named residual, not a new hazard annotation — the hazards model excludes lock families other than persistence rewrite — and the statements stay inside the existing transactional table-phase-11 placement. Deferred by name: extended statistics (the [import long tail plan](../plans/import-long-tail.md)); a `SET STATISTICS DEFAULT` emission and its PostgreSQL 17 floor under ADR 0024; an automated workspace strip tool for rollback; a lock-family hazard annotation; and the issue's out-of-scope work — inline `STORAGE`/`COMPRESSION` changes, generated columns, table parameters, and type-alias work. No new `CONTEXT.md` headword is introduced; the existing Column and Introspection vocabulary covers the change.

**Supersedes:** [ADR 0015](./0015-column-attributes-travel-the-model.md):17's "statistics targets" deferral item and [ADR 0014](./0014-catalog-index-canonicalization.md):17's "and statistics targets" deferral item only, both now delivered by this slice; the rest of each ADR stands, and neither ADR is rewritten.
