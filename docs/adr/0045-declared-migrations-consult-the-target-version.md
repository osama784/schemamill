# 0045 — Declared migrations consult the target version

**Date/Status:** 2026-11-28 · accepted

**Context:** [Issue #162](https://github.com/osama784/schemamill/issues/162) asked schemamill to reject by name a plan whose model carries a declaration the declared target version cannot express, instead of rendering it and losing — or failing — at apply. The issue was filed from #141, which produced [ADR 0024](./0024-synthesized-forms-consult-the-target-version.md): that decision put the PostgreSQL major into `renderSql` and gated only the renderer's **synthesized** reset forms, while its `:11` decision stated that "declarations the model carries render as declared at every target". [ADR 0012](./0012-constraint-attributes-travel-the-model.md):7 had earlier chosen to render PostgreSQL 18-only syntax as declared "because the source carried the declaration", and [ADR 0015](./0015-column-attributes-travel-the-model.md):15 stated the two floors without enforcing them. [ADR 0025](./0025-in-place-foreign-key-enforcement-flips.md):26 added a third target consumer with an equivalent fallback, while keeping target-below-18 drop/add output byte-identical and non-refusing; [ADR 0038](./0038-not-null-constraint-comments-travel-the-model.md):15 pinned a not-null comment at target 13 with no refusal, and [ADR 0043](./0043-render-refusals-are-reported-hazards.md):19 explicitly left "[t]he declaration-validation residual in that ADR … untouched". The residual was not harmless: at targets 13–17 an inline named `NOT NULL` parses but silently discards the name, a named `DROP CONSTRAINT` or `COMMENT ON CONSTRAINT` on the not-null fact resolves through `pg_constraint` and fails at apply with SQLSTATE 42704 (`constraint "<name>" for table "<table>" does not exist`), and `NOT ENFORCED` and explicit `COMPRESSION` are syntax errors on servers below their floors. The issue's Goal settles the scope question: a declaration the **model carries** must be validated, including one on a table the plan does not touch. A decision was needed on the authoritative fact source, the form floors, the hazard channel, the API route for the target model, and what rollback means when no workspace format changes.

**Decision:** `@schemamill/postgres` owns one pure collector, `declaration-facts.ts`, and the renderer's gate and the hazard analyzer derive their facts from it. The collector reads the plan and, when supplied, the target model; it renders no SQL and consults no catalog. Model-carried declarations are collected in model order (tables, columns, check constraints, foreign keys) even when the plan has no steps or never touches the declaring table; step-backed declarations follow in plan order and in emission order. `renderSql` calls `assertDeclarationsSupported(collectDeclarationFacts(plan, { targetModel: options.targetModel }), targetVersion)` **before** `assertNamesUnique`, so the first offender at target 13–17 is a declaration-floor refusal rather than a name-collision refusal. Emitters call the same helper defensively — inline `renderColumn`, named `add-not-null`/`drop-not-null`, not-null `comment`, `renderEnforcement` (with `TableIdentity` threaded through its callers, including the collapsed `ALTER CONSTRAINT … NOT ENFORCED` flip), `renderSetCompression` for an explicit method, the merged-`TYPE` carrier and standalone compression fields — but the collector is the single source of truth. `RenderOptions` gains an optional `targetModel?: Model`: when a caller holds the end-state model it supplies it (`plan` in both human and JSON modes, DDL `export`, and the live harness's plan-check renders); absent, only step-backed facts are validated, so existing library callers keep their behavior. `plan()` itself gains no parameter, no `Model` or workspace field is added, and `compare --target-version` keeps forwarding the major through the analyzer's existing options argument. Validation runs on zero-step plans too, matching DDL export; `--format json` and `--format markdown` export return before rendering and cannot refuse.

The form floors are stated as one table, correcting the four-row table in ADR 0024's `:15`–`:24`:

| Declaration | On a target below its floor | Loudness before this decision | Ruling now |
|---|---|---|---|
| Named `NOT NULL`, inline (`CONSTRAINT <name> NOT NULL` in `CREATE TABLE`/`ADD COLUMN`) or as an added table constraint (`ADD CONSTRAINT <name> NOT NULL`), floor **18** | 13–17 accept the inline form and **silently discard the name** — no `pg_constraint` row, so a later `COMMENT ON CONSTRAINT` fails; the table-constraint form is rejected at parse | silent for inline, syntax error for the added form | refused by name before any SQL is emitted, for both forms |
| Named not-null **drop** (`DROP CONSTRAINT <name>` on a `drop-not-null`) and **comment** (`COMMENT ON CONSTRAINT … ON …` on a `not-null` target), floor **18** | 13–17 have no `pg_constraint` row to resolve; both fail at apply with 42704 | loud at apply | refused by name before emission |
| `NOT ENFORCED` on a check constraint or foreign key, including the collapsed in-place foreign-key flip, floor **18** | 13–17 reject the statement at parse | loud syntax error at apply | refused by name before emission; a tightening `ENFORCED` flip with no `NOT ENFORCED` declaration keeps its drop/add pair |
| Explicit `COMPRESSION` method (`pglz`/`lz4`), floor **14** | PostgreSQL 13 rejects the statement at parse | loud syntax error at apply | refused by name before emission; synthesized `SET COMPRESSION default` keeps its separate ADR 0024 gate |
| Inline `STORAGE` (`CREATE TABLE … STORAGE <letter>`, PostgreSQL 16+) | **not gated**: the renderer never emits inline storage; it emits `ALTER … SET STORAGE`, valid on all of 13–18 | harmless, and no form reaches the server | named residual, not a declaration the renderer states; no floor and no refusal |

Each refusal is one library-level `RenderRefusalError` line, `refusing to render for PostgreSQL <target>: <capability> on <scope> needs PostgreSQL <floor> or newer`, with the table schema-qualified and identifiers minimally quoted: `named NOT NULL on <table> column <column>`, `named NOT NULL drop on <table> column <column>`, `NOT NULL comment on <table> column <column>`, `NOT ENFORCED on <table> constraint <name>`, and `COMPRESSION <method> on <table> column <column>`. Multiple offenders resolve by (model order, step index, fact order), so the first named offender is deterministic; the message names the capability requiring the floor, so the inline-name-loss case is honest rather than silent. Human `plan` still writes its display and one `schemamill: <message>` stderr line with exit 1; `plan --json` still writes one complete JSON document including `hazards` to stdout, then that one stderr line and exit 1; DDL `export` writes no artifact. No SQL is emitted on a refusal, so no refusal claims live evidence.

The same collector feeds `hazards.ts`, restricted to `origin: 'step'` facts below their floor: `render-refusal` gains a second entity shape, `unsupported-declaration` (`{ kind, schema, table?, declaration, targetVersion, floor }`), beside `name-collision`. `HazardEntity` is widened in core, the `Extract` on `render-refusal` covers both shapes, and every exhaustive consumer is updated — `format.ts`'s entity label and hazard clause (which names the form and floor), `json.ts`'s two mappers, the JSON contract tests' entity-key Records, and [the JSON output contract](../json-output.md). `step` stays the real plan index of the declaring step, so `schemaVersion` stays 1: the new entity kind is additive and changes no required shape ([ADR 0043](./0043-render-refusals-are-reported-hazards.md), [ADR 0033](./0033-json-output-envelope.md)). Human `compare --target-version <major>` reports step-backed declaration hazards without rendering. A model-only declaration refuses in `plan`/`export` but has no step to attach to and therefore no hazard and no sentinel step — a named asymmetry, not a gap in the refusal. No new Step kind is introduced, so `transactions.md` and the transaction classification stay unchanged.

**Consequences:** A declared target of 13–17 now refuses a plan or workspace carrying a PG18-only named `NOT NULL`, its named drop or comment, or `NOT ENFORCED`, and target 13 refuses explicit compression. This is the deliberate behavior change: because the default target remains 13 and the declaration is **model-carried**, a workspace with an unchanged named not-null on an untouched table now refuses without an explicit `--target-version 18` (or `--target-version 14` for compression), even though the old renderer accepted and silently lost its name. Plans with no affected declaration, and all valid declarations at or above their floor, render byte-identically; a no-diff workspace carrying an unsupported declaration now refuses on both `plan` and DDL `export` where `plan` previously skipped validation.

Rollback needs no workspace re-save: this decision adds no `Model` field, no workspace key, and no persistence format — only the optional render option `targetModel` and the exported collector/helper API. Reverting to a pre-slice binary reads the same workspace files unchanged; what changes is the SQL surface, since a plan that was accepted at an affected target now refuses until a higher target is declared or the declaration is removed. No live scene is added: a refusal emits no SQL to apply, so the 42704 cases and the parse floors stay pinned by unit, golden, and CLI tests, and CI remains the live authority. The corpus is 582 postgres tests + 63 scenes + 4 always-on live subtests = 649, with the five PostgreSQL 18 scenes floored; no local `SCHEMAMILL_TEST_PG_URL` was configured, so live pass/skip counts come from CI only.

Named residuals: `compare --json` still emits no hazards, including declaration hazards, so the asymmetry is between human and JSON `compare` as well as between step-backed and model-only facts; a dump-only rename of a not-null constraint cannot be preflighted, because `pg_dump` writes a named `NOT NULL` only for PostgreSQL 18 and newer and a pre-18 dump carries an unnamed fact with no name to validate; inline `STORAGE` keeps its no-floor residual because the renderer never emits it; import-time declaration flags, a warning mode, and a model/workspace target version stay deferred; backport checks beyond stable branches, live-PG verification of the apply-time 42704 cases (no SQL is emitted on refusal), and the RC cut (#260) are out of scope.

**Amendment by correction, not supersession.** Every accepted ADR below remains accepted and byte-unchanged; its clause is narrowed here, following the precedent ADR 0043:19 and ADR 0044:33 set (and ADR 0016's "accepted ADRs are immutable, so ADR 0014 stands as written and this paragraph is the correction").

- [ADR 0012](./0012-constraint-attributes-travel-the-model.md):7's "PostgreSQL 18-only syntax is rendered as declared: the renderer negotiates no server version, because the source carried the declaration" is narrowed: a declaration below its floor is now refused by name, and the target model participates even when the plan does not touch it. The model shapes, import canonicalization, and drop/add decomposition in that ADR stand.
- [ADR 0015](./0015-column-attributes-travel-the-model.md):15's "the version floors are stated, not negotiated" is narrowed for explicit compression (now enforced at 14): the inline `STORAGE` sentence is *not* corrected into a gate — inline storage is still never rendered, and the `ALTER … SET STORAGE` that is rendered stays valid on 13–18. Storage resets keep ADR 0024's separate 16 floor.
- [ADR 0024](./0024-synthesized-forms-consult-the-target-version.md):5's description of declaration validation as an open residual, `:11`'s "Declarations the model carries render as declared at every target", `:15`–`:24`'s four-row residual table (including its silent inline-name-loss row and harmless-storage row), `:26`'s "Fixing that gap needs its own slice and ADR", `:28`'s narrowing of ADR 0012/0015 to declarations, and its `:11` v1 sentence that export and compare take no flag are narrowed here. This is that slice and that ADR: declarations consult the target by name, the silent row is a refusal, the table is corrected above, and #178/#102 already consumed the flag deferrals as ADR 0043:19 records. The synthesized reset gates and the 13 default survive unchanged.
- [ADR 0025](./0025-in-place-foreign-key-enforcement-flips.md):26's "below 18 the renderer emits exactly today's drop+add pair, byte-identically, not a refusal" and `:30`'s "a form with an equivalent fallback selects the fallback" are narrowed: the fallback still applies to a pair with no `NOT ENFORCED` declaration, but a pair whose collapsed form would state `NOT ENFORCED` is refused below 18 by the declaration gate. The eligibility rules, the three legal transitions, and the default-target drop/add output for declaration-free pairs stand.
- [ADR 0038](./0038-not-null-constraint-comments-travel-the-model.md):15's "a `notNullComment` plan rendered at `--target-version 13` … still emits `COMMENT ON CONSTRAINT … ON …`, with no refusal" and `:19`'s deferred "declaration validation against the declared target (ADR 0024's residual)" are narrowed: the comment now needs floor 18 and refuses by name below it, closing that deferral. The `Column.notNullComment` shape, the comment-blind generated-name strip, and catalog congruence stand.
- [ADR 0043](./0043-render-refusals-are-reported-hazards.md):7's single `name-collision` entity shape and `:19`'s "The declaration-validation residual in that ADR is untouched" are narrowed: `render-refusal` carries a second, additive `unsupported-declaration` entity, and the residual is closed for step-backed facts while model-only declarations remain hazard-free by design. The claim namespaces, server-form names, baseline occupancy, `schemaVersion` of 1, and the `name-collision` CLI contract stand.
