# 0023 — Export projects the model as DDL or canonical JSON

2026-10-30 · accepted

**Context:** The canonical model had no projection out of the workspace. `plan` renders migration SQL for a baseline→target pair, but no command turns a model into a reviewable artifact, and DDL for any non-`public` schema was unusable because `plan()` had no schema step; the live harness only worked by pre-creating namespaces in `setupSql`. Export is named as a first-class artifact in the vision and core-domain map.

**Decision:** `schemamill export [--format ddl|json]` resolves the workspace from the current directory and prints one artifact to stdout. `ddl` is `renderSql(plan(emptyModel, model))`; `json` is `serializeModel(model)` re-exported from `@schemamill/core`. A new transactional `create-schema { schema }` step is synthesized for every schema used by a target object and absent from every baseline object's schemas, excluding `public`, deduped and name-sorted, at the head of global phase 1 before extension creates. It renders `CREATE SCHEMA IF NOT EXISTS <quoted schema>;`. The inventory is the schema fields of tables, sequences, views, and extensions plus identity sequence names; schemas reachable only through opaque text or a foreign key to an unmodeled table are not inventoried. Ordering is schemas → extensions → the existing plan order. Export never applies SQL, writes files, or changes the workspace; `--out`, a header, markdown, a JSON envelope, schema drops, and schema ownership/ACL/comments stay out and are named deferred.

**Consequences:** Every plan now creates the namespaces its target objects need; the step count becomes 34 (32 transactional) and the plan/render/CLI goldens are re-pinned deliberately. `IF NOT EXISTS` is idempotent and tolerates an unmodeled-but-existing namespace; it is deliberately not pg_dump's bare form because migration SQL may run against a live baseline whose empty schemas are not modeled. `serializeModel` becomes a public read-only projection (superseding the `workspace-population` preference), while `writeWorkspaceModel` remains the only persistence path; the CLI gains no second serializer. Residuals: empty schemas, schema drops, system schemas, and opaque-text schema references are out of scope; export is a projection, not a migration engine.
