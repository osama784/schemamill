# 0020 — Model persistence writes atomically

**Date/Status:** 2026-10-28 · accepted

**Context:** The accepted [ADR 0010](./0010-workspace-container.md) fixed the workspace container and deliberately kept the writer internal: `initWorkspace` wrote the model, `serializeModel` was exported for tests only, and a public writer was deferred by name. [#113](https://github.com/osama784/schemamill/issues/113) then let `init --from` write an imported model, but only while creating a workspace — its optional model parameter cannot update one that already exists. Snapshots ([#81](https://github.com/osama784/schemamill/issues/81)) and the studio ([#83](https://github.com/osama784/schemamill/issues/83)) both need to write a model into an existing workspace, and without a shared seam each consumer would invent its own serializer call, temp-file protocol, and failure mapping. [#120](https://github.com/osama784/schemamill/issues/120) settles that seam: atomic replacement, no marker or directory creation, failures in the result union, and one write helper shared with `init`. ADR 0010 stands as written; this ADR records the decision it deferred rather than revising it.

**Decision:** `writeWorkspaceModel(startPath: string, model: Model): Promise<WorkspaceWriteResult>` is exported from `@schemamill/core` and re-exported through `packages/core/src/index.ts`. The result union mirrors `WorkspaceInitResult`: `{ ok: true, root }` on success, `{ ok: false, diagnostic }` otherwise, and the writer never throws for an fs failure. It resolves the workspace root through the same lexical walk as `resolveWorkspace` — the walk is extracted into a private `findWorkspaceRoot`, `resolveWorkspace` becomes the walk plus the model read, and the writer becomes the walk plus a write. The model read is deliberately not performed: a corrupt or missing `model.json` is a state a repair write exists to fix, so the writer must not fail with `workspace-model-invalid` or `workspace-model-missing` before it can replace the bytes. The walk's failures — `workspace-not-found`, `workspace-inaccessible`, `workspace-marker-invalid` — surface unchanged, and the writer never creates a marker, a directory, or a workspace.

The write serializes with `serializeModel`, writes the bytes to a uniquely named temp file in `.schemamill/`, and renames the temp over `model.json` in the same directory, so the rename is a same-filesystem atomic replacement: a reader sees either the old or the new complete file, a failed write leaves the previous `model.json` intact, and the temp is removed best-effort on any failure after its path is chosen. The unique suffix keeps concurrent writers from clobbering each other's temp; the last rename wins. The writer replaces unconditionally — there is no merge policy, no locking, and no format versioning. Failures stay in the result union and reuse `workspace-io` with the existing `cannot write <path>: <reason>` shape; no new diagnostic code was warranted. `initWorkspace` shares the same private write helper, so creation and update emit identical bytes; `init` keeps its marker-removal cleanup because reusing that cleanup for an existing workspace would delete a user's model.

The rename has a permission-mode consequence, recorded rather than fixed: it installs the temp file's inode, so the new `model.json` takes the temp's umask-derived mode instead of preserving the previous file's mode. A read-only `model.json` is therefore replaced rather than refused, and a restrictive mode is dropped. Mode preservation is overwrite policy and stays deferred. [ADR 0005](./0005-framework-free-core.md)'s dependency-free rule is untouched: the writer adds only `node:fs/promises` (`rename`, `rm`, `writeFile`) and `node:crypto` (`randomUUID`), both built-in.

**Consequences:** Core now has a public write seam for the consumers the plans already name — snapshots and the studio — so neither has to own a second serializer, a temp-file protocol, or a diagnostic mapping. No CLI surface or user-facing output changes: `init` and `init --from` keep their behavior, bytes, and messages, and the writer is not called from `@schemamill/cli`. The contract is pinned by core unit tests: canonical bytes and round-trip, overwrite with no temp left behind, a hard-link discriminator proving the directory entry is replaced rather than the inode rewritten, nested start paths, a non-workspace creating nothing, corrupt-model and missing-model repair, temp-create and rename failures preserving the previous bytes and cleaning the temp, and the public re-export. The residuals are named, not hidden: fsync and durability; crash-time temp cleanup; Windows rename-over-existing behavior, unverified; permission-mode preservation; overwrite/merge policy; locking and concurrency; a stable format contract and versioning ([#54](https://github.com/osama784/schemamill/issues/54)); snapshots ([#81](https://github.com/osama784/schemamill/issues/81)); studio consumption ([#83](https://github.com/osama784/schemamill/issues/83)); and a CLI write surface. ADR 0010 remains the container's record and is not amended.
