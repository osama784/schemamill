## [Unreleased]

### Added

- **Views and materialized views travel the model** — `@schemamill/core`'s `Model` gained a required `views` array holding one `View` entity for both kinds, discriminated by a required `materialized` boolean and carrying a schema-qualified identity, an opaque whitespace-normalized `definition` in the server's deparsed spelling, and an optional `checkOption` (`local` or `cascaded`). `@schemamill/postgres`'s importer now reads `CREATE [OR REPLACE] VIEW` and `CREATE MATERIALIZED VIEW` instead of skipping them: it slices the body from the statement's raw SQL, strips a trailing check option or `WITH [NO] DATA`, reads the check option from the clause or a `check_option` reloption (the clause winning), keeps the last definition of a repeated identity (the dump loop-repair `CREATE OR REPLACE` included), and flags every inline attribute it cannot carry — reloptions, column lists, matview access method, tablespace, `IF NOT EXISTS`, `WITH DATA`, implicit populated state, and non-default persistence — while still importing the view; recursive views are skipped and named because the parser's rewritten body cannot be re-rendered, and `REFRESH`/`CREATE TABLE AS` keep their skips. `diff` appended `view-added`/`view-removed`/`view-changed` with the `materialized`, `definition`, and `checkOption` fields in that order; `plan` gained the transactional `create-view`, `drop-view`, and `replace-view` steps, dropping views before the table phases and creating them after, with plain-view changes rendered `CREATE OR REPLACE VIEW` and materialized or kind changes rendered as a `DROP` plus `CREATE … WITH NO DATA`. The renderer refuses a materialized `replace-view` with `RenderRefusalError`, the CLI prints view lines and gains a `views` compare/plan golden scene beside the new postgres `views.sql` golden, and the workspace model file gained a `views` section after `sequences` — always written, with a pre-slice file without the key reading as no views. The gated `view-round-trip` scene proves the round trip with a `crossImportChecks` seam that deep-equals the applied and target imports, so no test pins `pg_get_viewdef` text across server versions. Deferred, by name: view reloptions and persistence modeling, view and matview column lists and output columns, matview indexes, tablespace, access method, populated state and `REFRESH`, view dependency ordering, the matview rewrite hazard, view comments/grants/ownership, catalog introspection parity ([#71](https://github.com/osama784/schemamill/issues/71)), workspace versioning ([#54](https://github.com/osama784/schemamill/issues/54)), and recursive-view import; [ADR 0019](docs/adr/0019-views-and-materialized-views-travel-the-model.md) and the [views plan](docs/plans/views.md) record the decisions ([#89](https://github.com/osama784/schemamill/issues/89)).
- **Live catalog introspection: sequences and identity columns** — `@schemamill/postgres`'s live catalog read gained a `sequences` section, so a database built from a model's own plan now introspects to a model the existing `diff` considers unchanged, and deep-equal to the dump import, for standalone and owned sequences with their effective options and ownership, and for identity columns with generation mode, effective sequence options, and the real internal sequence name. The read joins `pg_class`/`pg_sequence` to `pg_depend`, partitioning `deptype 'a'` (`OWNED BY`) into `Model.sequences` with `ownedBy` and `'i'` into `Column.identity` — identity sequences never model as `Sequence` entries — passes every 64-bit option through as exact decimal text (`seqstart` is the declared `START WITH`, not stored state), and always carries the identity's actual `SEQUENCE NAME`, the only dump-reachable shape under PostgreSQL's same-schema invariant. An identity attachment that is missing, duplicated, non-identity, or non-integer throws, and a sequence owned by an unread relation is skipped and named rather than given a dangling owner. Sequence unlogged/temporary persistence and divergent identity persistence are flagged, not modeled; the identity diagnostic is gone from `columnDiagnostics`, while generation stays flagged. `docs/adr/0018-catalog-sequences-and-identity-columns.md` records the decisions ([#80](https://github.com/osama784/schemamill/issues/80)).
- **Brand kit** — the locked identity lands: root `DESIGN.md` (the visual conventions), the byte-identical kit under `docs/brand/` (marks, `squarecut` wordmark, exports with a sha256 manifest, brand sheet, font licence), a README lockup, and a `docs/brand/` bullet in the index ([#118](https://github.com/osama784/schemamill/issues/118)).
- **Docs count check** — a new zero-dependency `docs:counts` tool derives the plan's step-kind and table-phase counts and the live suite's scenes, tests, and PostgreSQL 16 skips from code, scans `docs/**/*.md` with literal patterns, and reports every stale claim as `file:line claimed vs actual`, printing each actual component and a summary. It is report-only and exits 0, including on a derivation or claim error; the implemented but unwired `--check` exits 1 on either. The scan exempts `CHANGELOG.md` snapshots, immutable accepted ADRs, and code comments, and `docs/docs-counts.md` records the sources, patterns, and residuals. Its first authoritative run on PostgreSQL 16.15 refreshed the four live-suite claims to 317 tests across 45 scenes with the three PostgreSQL 18 scenes skipped, and the identity and sequences plans' table-phase claims were corrected to eighteen ([#111](https://github.com/osama784/schemamill/issues/111)).
- **Live catalog introspection: constraints** — `@schemamill/postgres`'s live catalog read gained a `constraints` section — uniform rows over unique, check, foreign-key, and exclusion constraints — and a PostgreSQL 18 `notNullConstraints` section, and its `primaryKeys` rows gained deferrability and the temporal flag, so a database built from a model's own plan now introspects to a model the existing `diff` considers unchanged, and deep-equal to the dump import, for unique, check, and foreign-key constraints, a primary key's `DEFERRABLE`/`INITIALLY DEFERRED`, and PostgreSQL 18's named not-null constraints. The read resolves unique and foreign-key columns (and a foreign key's referenced table and columns) from `conkey`/`confkey`, reads a check's inner text from `pg_get_expr` through the importer's `normalizeSourceText` so a dump that spells the same expression agrees, maps enforcement to the model's three states from `convalidated`/`conenforced` (valid and enforced absent, `NOT VALID` as `not-valid`, the collapsed `NOT VALID NOT ENFORCED` as `not-enforced`), maps referential actions through the importer's letter mapping, and reads a unique constraint's `NULLS NOT DISTINCT` and `INCLUDE` from its backing `pg_index` row; constraint-backed indexes stay consumed by the existing `contype IN ('p','u','x')` join. Names strip by the importer's server forms — truncation included — with the twin guards shared through exported structure keys, and a not-null name strips against PostgreSQL 18's generated `<table>_<column>_not_null`. Unrepresentable state is flagged in the importer's grammar: unique `NULLS NOT DISTINCT`, `INCLUDE`, `WITHOUT OVERLAPS`, and the defensive `NOT VALID`; check `NO INHERIT` and the defensive deferrability; foreign-key `MATCH FULL`/`MATCH PARTIAL`, the delete-column list, and `PERIOD`; primary-key `WITHOUT OVERLAPS`; and not-null `NOT VALID`/`NO INHERIT`; an exclusion constraint is skipped whole and named because the model has no exclusion shape. Contract drift — an unknown kind or field, a constraint or not-null row on an unknown or partitioned table, a not-null row on a missing or not-`NOT NULL` column, a duplicate `(schema, table, conname)`, a duplicate not-null row per column, and primary-key rows that disagree — throws instead of canonicalizing. `docs/adr/0016-catalog-constraint-canonicalization.md` records the section shape, the check-text deparse congruence and its authored-spelling residual, the consumption correction to ADR 0014's `conrelid` guard, and the named exclusions. The gated suite gained `introspection-constraints` (named, unnamed, composite, and deferrable unique constraints; the check-expression battery; composite and self-referencing foreign keys, one referencing a standalone unique index on the same table to pin the `contype` filter; every non-default referential action; deferrability; and `NOT VALID` on a check and a foreign key) and the constraint flag scenes `introspection-flags-constraints`, `introspection-flags-constraints-15`, and `introspection-flags-constraints-18`; `constraint-attributes` and `not-null-constraint-names` gained `matches-import` assertions. On PostgreSQL 16.15 the suite is 315 tests across 45 scenes, 3 skipped — the PostgreSQL 18 scenes, skipped by name — and all 45 run on the CI's PostgreSQL 18. Deferred, by name: exclusion-constraint modeling; temporal (`WITHOUT OVERLAPS`/`PERIOD`) modeling; not-null `NO INHERIT` inheritance; domain constraints, constraint triggers, and inherited/partition copies; `USING INDEX` provenance; `ON UPDATE … SET NULL (cols)`; unique and foreign-key `NO INHERIT` catalog detection (a one-way diagnostic gap); authored check-expression spelling drift; import-side temporal and not-null silent drops (a named follow-up); cross-major deparse drift and version gating ([#57](https://github.com/osama784/schemamill/issues/57)); CLI/studio consumption ([#71](https://github.com/osama784/schemamill/issues/71)); and sequences and identity ([#80](https://github.com/osama784/schemamill/issues/80)) ([#79](https://github.com/osama784/schemamill/issues/79)).
- **Workspace population: `init --from` imports a DDL dump into a new workspace** — `@schemamill/cli`'s `init` gained `--from <dump>` (`-` reads stdin) and `--verbose`: the command reads a DDL dump through the same `importDump` entry point `compare`/`plan` use and creates the workspace with the imported canonical model instead of the empty one, so `compare` and `plan` run on a workspace the user did not hand-edit. Import diagnostics print on stderr under `source` — one counts line whenever there are findings, every `[error]` line always, and `[skip]`/`[flag]` lines under `--verbose`; any `error` diagnostic exits 1 and creates no workspace, while a skip/flag-only import still creates it and exits 0, and a clean import leaves stderr empty. A read or import failure prints `schemamill: …` and exits 1 before the target is touched; an existing workspace is still refused with the `remove <target>/.schemamill to re-create it` repair hint, and its model bytes are untouched. `@schemamill/core`'s `initWorkspace` gained an optional `model` parameter defaulting to the empty model — so plain `init` writes byte-identical bytes — and `serializeModel` stays internal ([#113](https://github.com/osama784/schemamill/issues/113)).
- **Persistence flips report a `table-rewrite` hazard** — `plan` and `compare` now report a `table-rewrite` hazard for every `alter-persistence` step, naming the table as `schema.table` and stating that `SET LOGGED` or `SET UNLOGGED` rewrites the table under an ACCESS EXCLUSIVE lock; the new certain-cost family sits beside the definite and state-dependent ones, and the line keeps the `step <n> <kind> <entity>: <clause>` shape. The analysis reads the step, not the model pair — a created or dropped unlogged table carries no `alter-persistence` step and reports nothing, while a hand-built step on a table absent from both models still reports — and both directions are pinned by unit tests, a format test, and the `column-attributes` plan and compare goldens ([#107](https://github.com/osama784/schemamill/issues/107)).
- **Auto-close on `dev` merges** — a new `Closes` workflow closed the issues a PR links with a closing keyword (`Closes`, `Fixes`, `Resolves`, and their `-s`/`-d` variants, case-insensitive) when that PR merged into `dev`, since GitHub's native auto-close only fires for merges into the default branch (`main`); the keyword parser and the close loop are pinned by `node:test` cases wired into the root `pnpm test`, API failures fail the run loudly while an already-closed issue is only a notice ([#109](https://github.com/osama784/schemamill/issues/109)).
- **Workspace consumption: `compare` and `plan` read the workspace model** — `@schemamill/cli`'s `compare` and `plan` accept the workspace-resolved canonical model as a side of a comparison: run anywhere below a workspace root, a single dump path is the target and the workspace fills the baseline, `--baseline-workspace` is that default's explicit form, and `--target-workspace` reverses the direction; the positionals became optional (`[baseline] [target]`), the command descriptions now read "between a baseline and a target", and the usage and `--help` bytes are re-pinned beside them. The workspace side resolves through `@schemamill/core`'s `resolveWorkspace` from the process cwd — the CLI never re-walks — so the nearest marker wins and a corrupt nearest root is reported, never skipped; two explicit paths keep today's behavior byte-identical, an explicit path is never silently overridden, and a workspace side contributes no import diagnostics. Every resolution failure — each of the six `WorkspaceDiagnostic` codes that can surface, `workspace-not-found` included — prints exactly one `schemamill: <message>` stderr line and exits 1 with empty stdout, closing the exit-1 mapping ADR 0010 deferred to the first consuming command; the ordered usage errors (both flags, a flag with two paths, or no dump path) are refused before any filesystem access ([#78](https://github.com/osama784/schemamill/issues/78)).
- **Live catalog introspection: column defaults and attribute representation** — a live database's column defaults and its table persistence, explicit collation, storage, and compression now read back as the canonical model, and the flags that named them are gone. `@schemamill/core`'s `Column` gained `collation` (opaque, whitespace-normalized text in the spelling a dump writes, `pg_catalog."C"`-style; absent means the type's default), `storage` (`plain` | `external` | `extended` | `main`), and `compression` (`pglz` | `lz4`), each present only when a source states it, and `Table` gained `persistence` (`unlogged`; absent means `LOGGED`, the server default); `ColumnAttributes` is the target-side carrier an `alter-column` restates from. `diff` appended the `collation`, `storage`, and `compression` field changes after `default`, carries an `attributes` payload on `column-changed` exactly when `type`, `collation`, `storage`, or `compression` differs, and reports a table's persistence flip as `persistence-changed`; `plan` gained the transactional `alter-persistence` step (table phase 13, later phases renumbered 14–18 — eighteen table phases and twenty-six step kinds) and copies the carrier onto `alter-column`. `@schemamill/postgres`'s importer reads a dump's inline `COLLATE` as written, its inline `STORAGE`/`COMPRESSION` qualifiers and post-data `ALTER TABLE ONLY … SET STORAGE`/`SET COMPRESSION` as the model words, `CREATE UNLOGGED TABLE`, and `ALTER TABLE … SET LOGGED`/`SET UNLOGGED`, and its renderer states `CREATE UNLOGGED TABLE`, an explicit collation inline after the type, and — for created, added, or altered columns — post-data `ALTER TABLE ONLY … SET STORAGE`/`SET COMPRESSION`, with `SET STORAGE DEFAULT`/`SET COMPRESSION default` restoring an absent target and a merged `ALTER TABLE … ALTER COLUMN … TYPE … [COLLATE …]` statement restating what its type change resets; only that merged statement keeps the bare `ALTER TABLE` form. The catalog read gained the default (`pg_attrdef`/`pg_get_expr`) and the explicit-only collation, storage, compression, and unlogged persistence gates (`attcollation` against `typcollation`, `attstorage` against `typstorage`, `attcompression`, `relpersistence`), so the covered flags — default, collation, storage, compression, unlogged persistence — disappear while generated and identity columns and temporary persistence keep their byte-stable flags; `docs/adr/0015-column-attributes-travel-the-model.md` records the rules. The workspace reader/writer admits and validates the new fields, the CLI prints the attribute samples, a `column-attributes` CLI golden scene pins compare and plan (the plan golden carries the single merged `TYPE … COLLATE …` statement and the `ONLY` form on every `SET`), and the gated live suite gained `column-attributes` (minServerMajor 16, with the physical catalog values checked and both imports pinned) and re-pinned `introspection-flags`; on PostgreSQL 16.15 the suite is 290 tests across 41 scenes, 2 skipped — the two PostgreSQL 18 scenes — and all 41 run on the CI's PostgreSQL 18. Deferred, by name: identity-column reading ([#80](https://github.com/osama784/schemamill/issues/80)); temporary and sequence persistence; statistics targets; storage parameters; typed tables and `ON COMMIT`; generated columns; persistence rewrite and lock hazards; authored default and collation spelling drift; storage removal below PostgreSQL 16; inline `STORAGE`/`COMPRESSION` rendering; CLI/studio consumption ([#71](https://github.com/osama784/schemamill/issues/71)); and version gating ([#57](https://github.com/osama784/schemamill/issues/57)) ([#77](https://github.com/osama784/schemamill/issues/77)).
- **Live catalog introspection: indexes** — `@schemamill/postgres`'s live catalog read gained an `indexes` section, so a database built from a model's own plan now introspects to a model the existing `diff` considers unchanged for plain btree column-list indexes — named and unnamed, unique and plain. The one read-only `psql` batch carries one row per index on an ordinary, non-partitioned table — table identification, stored name, `pg_get_indexdef`, `indisvalid`/`indisready`, and the tablespace name — with constraint-backed indexes excluded in SQL through `pg_constraint`'s `conindid` join and its `conrelid` guard, the catalog-side counterpart of the importer's `USING INDEX` consumption, so a primary key's, unique constraint's, or exclusion constraint's index never leaks as a standalone index. Out-of-envelope definitions skip whole and by name with the importer's reasons through `classifyIndexEnvelope`, the acceptance rules extracted from `translateCreateIndex` so both inbound paths run one source of truth, in the catalog-side grammar `skipped CREATE INDEX <schema>.<indexName> (<reason>)`; a row whose index is not `valid && ready` is skipped and named, and an index on a non-default tablespace is kept and flagged. Names canonicalize by the importer's discipline — a stored name equal to `synthesizedIndexName`'s server form strips back to unnamed, 63-byte truncation included, the twin guard kept for parity, collision-suffixed names staying named — and rows sort by stored name before the strip and stable-sort by `name ?? ''` exactly as `finalizeTable` does, so the model never depends on payload row order. `CONCURRENTLY` maps absent — unrecoverable from the catalog and never emitted by `pg_dump` — closing the canonicalization debt ADR 0008 named, with `docs/adr/0014-catalog-index-canonicalization.md` recording the rules; contract drift (an unknown field, a duplicate `(schema, indexName)` row, an unknown or partitioned table, or an unparseable definition) throws, and the existing table, column, and primary-key reads are unchanged. The gated live suite gained `introspection-indexes` (constraint-backed exclusion, the unnamed tie order, a plain unique index, and a truncated-name strip round-tripping to zero diagnostics and an empty `diff`), extended `introspection-flags` with the expression, partial, and `INCLUDE` index skips, and gained the PostgreSQL 15+-gated `introspection-flags-nulls-not-distinct`; expression, partial, and `INCLUDE` index modeling, constraint introspection ([#79](https://github.com/osama784/schemamill/issues/79)), cluster/replident flags, version gating ([#57](https://github.com/osama784/schemamill/issues/57)), tablespace and storage modeling, and CLI/studio consumption are deferred ([#76](https://github.com/osama784/schemamill/issues/76)).
- **Live catalog introspection: tables, columns, and primary keys** — `@schemamill/postgres` bound the `CatalogReader` seam with `catalogReader`, reading a live server's user schemas through one `psql -c` batch — one implicit transaction, one JSON document — with an empty `search_path` and `default_transaction_read_only=on`, and no client-library dependency. The read maps tables in canonical order, columns in attribute order, and primary keys in key order, stripping PostgreSQL's conventional `<table>_pkey` name exactly as the dump importer does; partitioned relations are skipped and named, and unlogged or temporary persistence and the deferred column states — defaults, generation, identity, explicit collation, storage, compression — are flagged and named, with generated suppressing the default flag. Transport failures and payload-contract violations (missing or wrong-typed fields, orphan or duplicate rows) throw; `docs/adr/0011-introspection-transport.md` records the decision. The gated live suite gained `introspection-tracer` (a model with quoted and mixed-case identifiers, composite and conventional primary keys, and a dropped column whose `attisdropped` row must be filtered, asserting an empty `diff` and a deep-equal model against the dump import) and `introspection-flags` (pinning the exact deferred-state diagnostics) ([#55](https://github.com/osama784/schemamill/issues/55)).
- **Workspace container: layout, resolution, and `init`** — `@schemamill/core` gained `resolveWorkspace` and `initWorkspace` plus the `WORKSPACE_DIR_NAME`/`WORKSPACE_MODEL_FILE_NAME` constants: a workspace root is a directory holding a hidden `.schemamill/` directory whose `model.json` is the bare canonical model, and resolution is lexical — no `realpath` — walking to the filesystem root by `dirname`, returning the nearest marker, reporting a corrupt nearest root instead of skipping it, and distinguishing an absent marker from an unreadable one (`workspace-inaccessible`) through a ten-code `WorkspaceDiagnostic` union. `init` creates the target when absent, claims the marker atomically, writes the exact empty model, and refuses a target file, an existing marker (with the `remove <target>/.schemamill to re-create it` repair hint), and a directory inside an existing workspace (ancestors only, so a workspace containing another is allowed). The reader fails closed on unknown keys at every level, validates canonical integer strings, referential actions, sequence data types, and identity generations, and names the failing path. `@schemamill/cli` gained `schemamill init [path]`, printing `Initialized workspace at <absolute path>` and exiting 0, or the diagnostic on stderr and exit 1. A public writer, snapshots, and studio consumption remain deferred ([#54](https://github.com/osama784/schemamill/issues/54)).
- **Core mutation-testing harness** — `@schemamill/core` gained a StrykerJS 10.0.0 mutation-testing setup with `@stryker-mutator/tap-runner` and `@stryker-mutator/typescript-checker` pinned as devDependencies: `pnpm mutation:core` runs the full package mutation run against the existing `node:test` suite, and `pnpm mutation:check` is a scoped sanity check that derives the `src/diff.ts:sameOwner` anchor from the source at runtime, runs a real Stryker run, and fails when the committed config, coverage, or kill signal regresses. A new `Mutation` workflow runs the check and the full run on core-touching PRs, on `workflow_dispatch`, and on a weekly schedule (Node 24 on `ubuntu-24.04`, 60-minute timeout, `packages/core/reports/` uploaded as the `mutation-report` artifact, `if-no-files-found: error`); it is intentionally not part of the required `verify` matrix or the five gates, and no score gate is wired yet (`thresholds.break: null`) — `docs/mutation-testing.md` records the tool evaluation, both commands, the shared config, the CI shape, the survivor-triage protocol, and the anchor's re-aim contract ([#52](https://github.com/osama784/schemamill/issues/52)).
- **Compare prints hazards** — `@schemamill/cli`'s `compare` now plans the pair and prints the same `Hazards:` section `plan` prints, after the diff and separated by one blank line, only when the analysis finds anything, so a clean diff's stdout is unchanged. The hazard step numbers are plan-relative — `compare` prints no step list, so each `step <n>` names the step `schemamill plan` would number `<n>` for the same pair — the help text mentions hazards, and the `hazards` and `identity` compare goldens are re-pinned beside a golden-vs-golden test asserting both commands pin the same block. Exit codes are unchanged ([#51](https://github.com/osama784/schemamill/issues/51)).

### Changed

- **Temporal and `NO INHERIT` constraint grammar is flagged on import** — `@schemamill/postgres`'s dump importer now reports the constraint attributes it cannot carry instead of dropping them silently: primary-key and unique `WITHOUT OVERLAPS`, one `PERIOD` per foreign key (either side or both), and not-null `NO INHERIT` in every shape (inline, table-level, `ALTER TABLE … ADD`, named or unnamed); each constraint still imports with its representable identity, and the messages mirror the catalog read's wording (`dropped WITHOUT OVERLAPS on primary key t_pkey from public.t`, `dropped PERIOD on foreign key f_period from public.t`, `dropped NO INHERIT on not-null constraint nn from public.t`); temporal and inheritance modeling stays deferred ([#124](https://github.com/osama784/schemamill/issues/124)).
- **Compare spells constraint attributes** — `@schemamill/cli`'s `compare` now prints the attribute fields that differ on a changed primary key, unique constraint, check constraint, or foreign key — `enforcement`, `deferrable`, and `initially deferred` — as the model's raw values (`true`/`false`, `(none)` when a side omits the field), comma-joined after the existing fields on the same line and omitted when the change is name- or column-only, so an attribute-only change no longer reads the same as an unchanged constraint; the foreign key line also loses its dangling trailing `: `. The `constraint-attributes` compare golden is re-pinned ([#100](https://github.com/osama784/schemamill/issues/100)).
- **Long-tail import diagnostics: corrected labels and pinned families** — `@schemamill/postgres`'s dump importer now reports the long-tail families it skips by their SQL instead of by parser node keys, and corrects the two labels that misreported it: `CreateTableAsStmt` discriminates `objtype` so a materialized view reads `skipped CREATE MATERIALIZED VIEW <schema.mv>` while `CREATE TABLE AS` keeps its bytes, and `GrantStmt` discriminates `is_grant` so `REVOKE` reads `skipped REVOKE statement` (object `REVOKE`, both `REVOKE SELECT` and `REVOKE ALL`) while `GRANT` keeps `skipped GRANT statement` (object `GRANT`). `REFRESH MATERIALIZED VIEW <schema.mv>` is named instead of falling back to `RefreshMatViewStmt statement`; `CREATE RULE <name> ON <schema.table>`, `CREATE POLICY`, and `ALTER POLICY` name their object and table; the four row-security `ALTER TABLE` subtypes read `ENABLE`/`DISABLE`/`FORCE`/`NO FORCE ROW LEVEL SECURITY`; and `COMMENT ON MATERIALIZED VIEW` spells the SQL keyword by reusing `alterObjectKind`; the keyword change covers `MATERIALIZED VIEW` and `FOREIGN TABLE`, and the remaining comment keywords keep their bytes. A new `LONG_TAIL_DUMP` fixture pins the complete ordered diagnostic array — `kind`, `code`, `object`, `message`, position deliberately unpinned — for extensions, views, materialized views, `CREATE TABLE AS`, refresh, triggers, functions, procedures, rules, policies, `ALTER POLICY`, RLS enablement, foreign tables, comments, GRANT, both REVOKEs, and the `LIKE`/`INHERITS` flags, and a second test pins the partial shapes (`LIKE` imports zero columns; `INHERITS` imports its own columns only). Deliberately left generic as named residuals: type definitions (slice J), role grants and `ALTER DEFAULT PRIVILEGES` (slice F, #92), tablespace DDL (slice K), shared nodes for non-sequence `DROP`/`RENAME`/`SET SCHEMA`, and the beyond-inventory families on their own slices; `CREATE OR REPLACE RULE`/`DO ALSO`/`DO INSTEAD` variants collapse into one wording, and `SELECT … INTO` stays `SELECT statement` ([#88](https://github.com/osama784/schemamill/issues/88)).
- **Generated names and omitted declarations round-trip** — `@schemamill/postgres`'s name prediction now mirrors PostgreSQL's own naming instead of approximating it: `truncateIdentifier` returns an explicit identifier's server form — the longest prefix of at most 63 UTF-8 bytes that never splits a character — and `makeObjectName` shrinks the longer of the table and column parts byte by byte, a tie shrinking the column part, before each part clips at a character boundary; the label is never truncated, and the column-addition loop stops after the part that brings the running length to `NAMEDATALEN`. Every `synthesized*Name` — index, primary key, unique constraint, foreign key, check constraint, and not-null name — is the mirror, so short inputs stay byte-identical and long inputs predict the name the catalog stores. Import canonicalization compares a dumped name against that server form, so a generated name PostgreSQL truncated silently strips back to unnamed exactly as a short one does — collision-suffixed names (`_idx1`, `_key1`, …) stay named, and the twin guards and the not-null merge are unchanged — and synthesized drops render the server form, fixing the pre-fix bug where a long-named unnamed drop named the assembled form, which PostgreSQL clipped to a different name and refused to drop. The duplicate-name guard resolves index names through their server forms, so two unnamed predictions that only collapse under truncation, or a prediction against an explicit name equal to its server form, refuse with `RenderRefusalError` before any SQL renders, with a claimant's untruncated prediction shown beside the collapsed name; non-collapsing messages stay byte-identical. `@schemamill/core`'s `diff` treats a foreign key that omits `referencedColumns` as equal to an explicit list exactly when that list equals the omitting side's own model's referenced-table primary key, in primary-key order — both sides empty stay equal regardless of the referenced table's key, an absent referenced table or one without a primary key stays unequal, two explicit lists still compare element-wise, and the equivalence replaces only the `referencedColumns` clause, so no resolved list enters a payload, identity, or step — closing the residual where a dump that states the list a declaration omitted read as changed after apply. Output changes only for names longer than 63 bytes and the omitted-list equivalence: short names stay byte-identical and no CLI golden changes.
